## 1. 人口は 10 で止まらない。止める仕組みがそもそも無い

### 実測（種 20260819・オーナーは何もしない）

| 世代 | 人口 | フェーズ | 初戦の合図 | 備蓄 |
|---|---|---|---|---|
| 0 | 2 | 村 | — | 24.0 |
| 3 | 9 | 村 | — | 15.4 |
| **4** | **15** | 村 | **立つ** | 20.5 |
| 5 | 26 | 村 | 立つ | 33.3 |
| 10 | 34 | 村 | 立つ | 0.0 |
| 20 | 50 | 村 | 立つ | 29.2 |
| 30 | 87 | 村 | 立つ | 0.0 |
| 60 | 128 | 村 | 立つ | — |

戦争に一度も行かなければ、**60 世代目に人口 128 でまだ「村」**。

### なぜ止まらないか

`world.js:457` がやっているのは、人口を止めることではなく旗を立てることだけ。

```js
if (w.people.size >= PHASE_THRESHOLD[1]) w.reachedThreshold = true;   // world.js:457
```

その下（`world.js:458〜475`）は

- 初戦がまだ → `w.pendingFirstWar = true`（`world.js:462`）を立てて、**フェーズ移行だけ**を止める
- 初戦が済んだ → `w.phase = PHASE.TRIBE`（`world.js:468`）

繁殖（`breedGeneration`）にも `stepTick` にも、村フェーズの人口上限を見る行が1行も無い。
実際に効いている天井は3つだけで、どれも 10 とは無関係。

- `MAX_POP = 400`（安全弁）
- `LAND_MAX = 45` × `POP_PER_LAND = 2.6` ＝ 密度の基準 117
- 食料（飢えると餓死するが、床があるので絶滅はしない）

### さらに悪いこと：10 という数字を人間が見ることがない

人口は世代境界で 2 → 4 → 7 → 9 → **15** と跳ぶ。10 を通過しない。
それでも `main.js:224` のモーダルは「**村は10体で止まります。これ以上は増えません。**」と出る。
20 種で測った合図時点の平均人口は **11.0 体**、最大 **16 体**。画面の文と盤面の数が最初から食い違う。

## 2. 初戦が 5対5 にならないのは、相手の国に人がいないから

### 実測（20 種・UI が薦めるとおり「いちばん強さの数字が小さい相手」を選ぶ）

| 結果 | 件数 |
|---|---|
| 5対5 になった | 17 / 20 |
| 5対2 になった | 2 / 20 |
| 5対4 になった | 1 / 20 |
| 自国が滅んでいて 0対1 | 1 / 20（別集計、下記5節） |

`startWar` は初戦だけ相手を同数に揃える（`battle.js:176〜181`）が、揃えるのは
`Math.min(n, pool.length)`（`battle.js:247`）なので、**相手世界に5人いなければ揃わない**。

第4〜6世代のライバル国は人口 6〜7 が普通で、いちばん弱い国はしばしば人口 2〜4。
UI は `opponents.js:59` で「迷ったら、いちばん上（＝強さの数字がいちばん小さい相手）」と薦めるので、
プレイヤーは構造的に**いちばん人がいない国**を選ばされる。

### 相手側に子どもが混ざる

初戦の相手5体の年齢を実測すると

```
アガルタ: 相手世界 pop6（うち成人3） → 出てきた5体の年齢=[6,2,3,1,1]   ← 1歳が2体
ヒエラ  : 相手世界 pop7（うち成人4） → 出てきた5体の年齢=[6,3,6,2,1]   ← 1歳が1体
```

`roster.js:175` の `nationView()` は `filter(p => p.age >= 2)` で子どもを外している。
一方 UI が通る `adapter.js:166` は `people: [...w2.people.values()]` と**全員を渡している**。
同じ「相手国」なのに、ライバル同士の戦争と、プレイヤーの戦争とで中身が違う。

## 3. 「国の強さ7」が10国横並びになる理由

### 実測

```
gen 0 : アガルタ:7 デメテル:7 ミレト:7 スパルティ:7 アレクサ:7 …（10国すべて 7）
gen 4 : アガルタ:26 デメテル:100 ミレト:98 スパルティ:47 アレクサ:66 …（全部ばらける）
gen12 : 352 / 2639 / 1004 / 389 / 1869 / 224 / 136 / 171 / 1416 / 897（10値とも別）
```

つまり **7 が並ぶのは「ロスターが第0世代のまま」のときだけ**。

原因は `roster.js:51〜56`。10国は「経営思想だけを変えた対照実験」にするため、
**回答も創始者の種も共通**にしてある。

```js
const answers = new Array(12).fill(0.5);
const FOUND_SEED = 0x5eed1234;
const world = createWorld(nseed, answers, { foundSeed: FOUND_SEED });
```

第0世代では 10国すべてが「人口2・アダムとイザナミ・産出0・民心0.6」の同一状態なので、
`world.js:1158` の国力式が同じ 7 を返す。ここは設計どおりで、バグは
**「ロスターを1世代も進めないまま対戦相手一覧を出す経路がある」**こと。

見つかった経路は2つ。

1. `main.js:566` の `demoSetup()`（`?dev=1` → 「開発用：部族フェーズから開始」）。
   内部の `runGens()` は `stepTick` / `advanceGeneration` しか呼ばず、**`stepRoster` を呼ばない**。
   世界だけ6世代進み、ロスターは第0世代のまま → 一覧は全部 7、初戦は 5対2。
   実測でも「roster を進めない」条件では 5種すべてが 5対2 になった。
2. `main.js:82` の `createRoster` が例外を投げると `state.roster = null` になる。
   このとき `opponents.js:21` の `api.listOpponents(null)` は
   `TypeError: Cannot read properties of null (reading 'nations')` で落ちる。
   → 対戦相手の画面が開かない＝「戦いにいけない」。

なお、`advanceRoster` 自体は 3種 × 60世代を回しても一度も例外を出さず、
10国中 9〜10国が生き残った（ロスター内の戦争 30〜34 件）。ロスター本体は健全。

## 4. 捕虜・国境・戦後処理

### 4-1. `captiveOptions` が落ちる条件を特定した

`battle.js:524〜526` に防御が1つも無い。

```js
export function captiveOptions(battle) {
  const won = battle.outcome && battle.outcome.winner === 'home';   // 525行
  const survivors = battle.sides.away.units.filter((u) => !u.dead).length;
```

`battle` が `undefined` のとき、**525行で
`TypeError: Cannot read properties of undefined (reading 'outcome')`** になる。
報告されている症状と完全に一致する（実測で再現済み）。

ただし **`adapter.js` 越しの正規経路（`view._sim` を渡す）では落ちなかった**。
6通りの呼び順 × 5種 = 30 通りを試して例外ゼロ。

| 試した順番 | 結果 |
|---|---|
| 通常（ロスターを進める） | 5種とも例外なし・5対5 |
| ロスターを止めたまま | 5種とも例外なし・5対2 |
| 相手を選ばずゴースト | 5種とも例外なし・5対5 |
| 途中で降伏 | 5種とも例外なし |
| `settleWar` を先に呼ぶ | 5種とも例外なし |
| 捕虜を誅殺 | 5種とも例外なし |
| `takeCaptives` を2回 | キャッシュが返る・例外なし |
| `settleWar` を2回 | 2回目は0件・例外なし |
| 同じ捕虜に2回 `borderDecision` | `null` が返る・例外なし |

したがって落ちるのは「`view._sim` が無いものを `captiveOptions` に渡した」ときだけ。
**sim 側に `if (!battle || !battle.sides) return {...}` が無いのが根の問題**で、
渡し間違いが例外になって画面が死ぬ。

### 4-2. 決着前に `captiveOptions` を呼んでも例外にならない（もっと悪い）

決着前に呼ぶと `won: false`, `axes: []` が返る。`border.js:11` は

```js
let phase = battle.outcome === 'win' ? 'axis' : 'draw';
```

なので、決着前に国境画面が開くと **軸を選ぶ画面が丸ごと飛ばされて、いきなり抽選が走る**。
実測で決着前の `takeCaptives` も普通に1体返した。勝者の特権（軸を1つ選べる）が黙って消える。

### 4-3. 呼び順が UI と sim 内部で逆になっている

| | 順番 |
|---|---|
| UI（`border.js`） | `captiveOptions` → `takeCaptives` → `borderDecision` → `settleWar` |
| ライバル同士（`roster.js:112〜122`） | `applyRout` → `settleWar` → `takeCaptives` → `transfer` |
| ヘッドレス検査（`test/integration.js:336〜344`） | `captiveOptions` → **`settleWar`** → `takeCaptives` → `borderDecision` |

`settleWar` の中で `applyRout`（敗走の追い討ち）が走る。UI の順番だと
**追い討ちより先に捕虜を引く**ので、追い討ちで死んだはずの個体を連れ帰れる。
実測でも捕虜を引いた時点の away 戦死者と `settleWar` 後の戦死者が違う世界が出る。

### 4-4. 相手国から人が減らない

実測（種 20260819、アガルタから捕虜1体を連れ帰った直後）

```
自国    pop 17 → 16
相手国  pop  6 → 6      ← 連れ去った1体が相手世界にまだ生きている
捕虜モロス: away側の状態 = 生存
```

`roster.js:167` の `transfer()` は `kill(source.world, src, '捕縛')` で元の国から本当に消す。
プレイヤー経路（`adapter.js:555` の `A.settleWar`）は `sim.settleWar(w, sb, rng)` しか呼ばず、
`applySideLosses(相手世界, battle, 'away', rng)` も `kill` も呼ばない。

結果：**同じ個体が2つの世界に同時に存在し、相手国はプレイヤーとの戦争で誰も失わない。**
同じ国と何度戦っても相手は減らない。

### 4-5. 捕虜が0体でもフェーズ2に上がる

`settleWar` は `battle.firstWar` なら無条件に `firstWarDone = true`（`battle.js:736〜739`）。
相手を殲滅すると `takeCaptives` は0体を返す（`battle.js:557`「殲滅した瞬間、自分の報酬が消える」）。

実測（ロスターを止めた状態・種 20260819）：**5対2 → 勝利 → 捕虜0体 → 次の世代でフェーズ2**。
設計文書 2266 行「10体到達 → 初戦（5対5）→ 捕虜1体 → フェーズ2」の
**「捕虜1体」だけが抜けた状態でフェーズ2が始まる**。外来血ゼロなので色も変わらない。

### 4-6. 負けたほうが捕虜を多く取れる

P2 の戦争を 12 種で実測（`CAPTIVE_COUNT[2] = [1,5]`）。

| | 引けた数 | 平均 |
|---|---|---|
| 勝った戦 | 2,2,1,2,2,3,2,1,2,2,1,1,1 | **1.69 体** |
| 負けた戦 | 1,3,2,2,5,3,5,5,4,2,3 | **3.18 体** |

原因は `battle.js:563` の `Math.min(alive.length, lo + rng.int(hi - lo + 1))`。
勝つと相手を殺しているので `alive.length` が小さく、上限に頭を打つ。負けると相手は無傷なので5体まで引ける。
**負けたほうが得**という向きになっている。

## 5. 食料経済：村の第7世代で1回目の飢饉、第24世代で2回目

### 5-1. オーナーが何もしない場合（autoAssign 任せ）

| 世代 | 人口 | 農 | 狩 | 土地係数 | 産出/tick | 消費/tick | 備蓄 | 累計餓死 |
|---|---|---|---|---|---|---|---|---|
| 1 | 4 | **0** | 2 | 1.00 | 2.47 | 2.24 | 29.3 | 0 |
| 3 | 9 | **0** | 4 | 1.00 | 2.62 | 4.81 | 15.4 | 0 |
| 6 | 36 | **0** | 15 | 1.00 | 13.75 | 19.03 | 32.1 | 0 |
| **7** | 39 | 5 | 20 | **0.64** | 16.48 | 24.23 | **0.0** | 1 |
| 9 | 38 | 4 | 26 | **0.32** | 21.80 | 26.42 | 0.0 | 5 |
| 17 | 47 | 11 | 24 | 0.41 | 28.83 | 31.98 | 0.0 | 8 |
| 24 | 89 | 27 | 42 | 0.51 | 49.86 | 60.95 | 0.0 | 15 |

破綻の因果は3段。

1. **第1〜6世代の農夫が 0 人。** `autoAssign`（`world.js:564〜609`）は
   `if (dad && … && rng.next() > transparency) p.role = dad.role`（`world.js:581`）で
   父の役を継がせる。創世のアダムが狩人なので、村中が狩人になる。
2. 農夫が0人だと `updateLand()`（`world.js:352〜`）の開墾が走らない。土地は
   `LAND_DECAY = 0.020` で痩せるだけになり、**18.0 → 15.8 に減る**。
3. 人口が増えて働き手が土地の0.7倍を超えると `landFactor` が落ちる
   （`world.js:178`：`1 / (1 + 2.5 * (ratio - 0.7))`）。第7世代で 0.64、第9世代で **0.32**。
   1人あたりの産出が3分の1になる。

つまり **食料が尽きるのは「食べすぎ」ではなく「土地に対して働き手が多すぎる」から**で、
その土地を減らしたのは配役の世襲バイアス。

### 5-2. オーナーが全員を畑に置いた場合（`assignRole` で固定）

| 世代 | 人口 | 農 | 土地係数 | 産出 | 消費 | 備蓄 | 累計餓死 |
|---|---|---|---|---|---|---|---|
| 6 | 75 | 21 | 1.00 | 28.96 | 37.34 | 150.6 | 0 |
| 8 | 87 | 61 | 0.40 | 41.52 | 59.85 | 0.0 | 3 |
| 17 | 150 | 52 | 0.65 | 59.40 | 75.73 | 168.9 | 18 |
| 19 | 128 | 87 | **0.27** | 47.52 | 88.08 | 0.0 | 55 |
| 24 | 84 | 62 | 0.31 | 50.65 | 57.90 | 0.0 | **113** |

**正しく遊ぶほうが悪化する。** 農夫を増やすと開墾が進んで土地が `LAND_MAX = 45` まで伸び、
人口が 150 まで膨らみ、そこで土地が頭打ちになって 113 体が餓死する。
オーナーの操作が「人口爆発の燃料」にしかなっていない。

### 5-3. 子どもの扶養比率

好況期には人口の 46〜55% が子ども（`CHILD_CONSUME = 0.45`）。
実測で消費の 30〜55% が子どもの分になる世代がある。人口の振動がここで増幅される。

### 5-4. 村のまま滅ぶ世界が 5%

40 種で村フェーズを回した結果：

- 初戦まで到達 **38 / 40**
- **人口0で絶滅 2 / 40**（種 20280066 は第11世代、種 20299313 は第19世代）
- 40世代回っても10体に届かない 0 / 40

絶滅しても止まる仕組みが無い。人口0のまま `startWar` を呼ぶと **0対1** の戦争が成立して、
その後も普通に進む。

## 8. ヘッドレス検査が踏んでいない順番

`test/integration.js` は `src/ui/adapter.js` の `makeAdapter()` を使っていて、そこは正しい。
踏んでいないのは中身。

| 検査がやっていること | 実機がやっていること |
|---|---|
| `makeGhost()` で作った相手と戦う（`integration.js:321`） | ロスターの実在国と戦う（人口2の国が混ざる） |
| `captiveOptions` → **`settleWar`** → `takeCaptives`（`:336-338`） | `captiveOptions` → `takeCaptives` → `borderDecision` → **`settleWar`** |
| `pendingFirstWar` を立てずに戦う | 初戦（`firstWar = true`）の分岐を通る |
| 人口・フェーズを検査しない | 10体で止まる前提でモーダルが出る |
| 相手世界の損耗を見ない | 相手が減らないことに誰も気づかない |

「動く順番」しか踏んでいない、という見立ては実測と一致する。
ただし**逆順にしても例外は出ない**（実測）。検査が見逃しているのは例外ではなく**結果の食い違い**。
