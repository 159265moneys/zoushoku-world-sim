## A-1. 数字が増えるだけの画面をやめる ★最重要

> 「なんか今数字だけパカスカ増えていって意味不明なので、なんとかビジュアルでもわかるようにしたい」

現状、プレイヤーが受け取る情報のほぼ全部が「数字が変わる」だけで届いている。
上帯の7項目、個体の33座位、団結、練度、国の強さ——すべて数字。
**数字が動いたことは分かるが、何が起きたのかは分からない。**

### 満たすこと

1. **状態は、まず絵で分かること。** 数字はその裏づけとして添える。順序を逆にしない。
   例：食べ物が減っているなら、まず盤面（畑・備蓄）が痩せて見える。数字はその横に置く
2. **変化は、変化として見えること。** 前の値が分からない数字は、増えたのか減ったのかすら伝わらない。
   増減の向き・勢いを、色と形と動きで出す
3. **数字を出すなら、必ず意味を添える。** 「82」だけの表示を作らない
   （用語班の辞書＋ホバー説明の仕組みに接続する）
4. 対象は上帯7項目・個体パネル・戦闘・年代記・報告のすべて。例外を作らない

### 制約

- **スプライト（画像素材）は入れない。** オーナーの明言。Canvas の手続き描画だけで解く
- 個体の見た目は「円＋縦長の目2つ」のまま（既定の方針 C を維持）
- 村はマップにする（既定の方針 C。畑・狩り場・訓練場・中心・辺境の背景が見て分かること）

## A-3. 「戦いに行けない」の有力な原因（要検証）

オーナーが最初に挙げた「戦いにいけない」は、2周の実機テストでは再現しなかった。
ただし `ui/adapter.js` の `refreshWarReady()` に、無言で戦争を封じる条件がある：

```
const cooled = (w.gen - (w.lastWarGen ?? -99)) >= 2;   // 前の戦から2世代
const idle   = !(w.borderQueue && w.borderQueue.length);
w.warReady = !!(enough && cooled && idle);
```

**一度戦うと、次の2世代は「戦いに行く」が消える。理由はどこにも表示されない。**
P2 では1世代＝実時間60分（×1）なので、**最大2時間ボタンが出ない**。
これが「戦いに行けない」の正体である可能性が高い。

→ ロジック班：不応期を残すなら**残り時間を必ず画面に出す**こと。
　 消えるボタンは「壊れている」と読まれる。

# A-4. 個体の記号体系を作り直す（2026-08-20 追加・確定）★キャラ班/描画班の最上位前提

オーナーの指示（原文）:

> キャラの大きさ、濃度、明るさ、目が意味不明なので完全に撤廃。
> 年齢は大きさ＋年輪みたいにして。熟練度は丸の数＝細胞の数を少しずつ増やして。
> 目つきってなに？鋭いからなんなん？

## 撤廃するもの（既存の設計を破棄する）

`world-sim-design.md`「ビジュアル」節と `ui/color.js` の現行マッピングのうち、以下を**捨てる**。
仕様書のほうが古い。この A-4 が優先する。

| 捨てるもの | いま何を表していたか | 捨てる理由 |
|---|---|---|
| **彩度（濃さ）** | 練度 | 見て分からない。濃い/薄いの比較が成立しない |
| **明度（明るさ）** | 体力・年齢 | 同上。しかも年齢は大きさへ移す |
| **目2つ（大きさ）** | 感応 | **感応は sim が一度も読まない死んだ座位。**何も起きない数字を描いていた |
| **目の細まり** | 恐怖 | 目ごと撤廃 |
| 大きさ（旧・体格） | 体格 | 意味を年齢に付け替える（形自体は残す） |

**特記：** `ui/panels/inspector.js` は感応に「気配に気づく力」という効果を書いている。
実装には存在しない。仕様書の原則「事実は常に正確に見える」に反する**嘘の表示**なので、
撤廃と同時にこの文言も消すこと。同じ性質の死んだ座位が他に2つある（世代間伝承意欲・懐疑）。

## 新しい記号体系

個体は「細胞のかたまり」として描く。**増殖というタイトルとカビというモチーフに、記号のほうを合わせる。**

| 表すもの | 記号 | 備考 |
|---|---|---|
| **年齢** | **全体の大きさ ＋ 年輪** | 育つほど大きく、輪が増える。老いも輪で読める |
| **熟練** | **細胞（丸）の数が少しずつ増える** | 0から始まり、使った仕事の分だけ増える。数えられること |
| **血統** | **色相**（据え置き） | 混血は中間色。彩度・明度は使わない＝**色相だけで表す** |

## この変更で行き場を失うもの（キャラ班が提案し、オーナーが裁定する）

撤廃した3チャンネル（彩度・明度・目）が担っていた情報のうち、次は**まだ担当が無い**。
勝手に数字へ戻さないこと。この語彙（大きさ・年輪・細胞の数・色相・輪郭・動き）の中で解くこと。

1. **体力／ケガ** — 旧・明度
2. **恐怖（戦闘中）** — 旧・目の細まり。戦闘の見どころそのものなので必須
3. **疲れ／不満** — 現状どこにも出ていない
4. **局長の印・よそ者の印** — いまは金/白の輪。輪は年輪と衝突するので作り直す

## 描画の予算（描画班）

細胞を個体ごとに描くと、円の総数が跳ね上がる。
- 人口150体 × 熟練上限の細胞数 = 何個になるかを先に決め、1フレームの予算内に収めること
- 小さく描いたときに細胞が潰れて団子にならない下限サイズを決めること
- 「数えられること」が熟練表現の生命線。数えられない密度になったら別の出し方に切り替える規則を書くこと

# A-5. 行き場を失った4件の裁定（2026-08-20 / オーナー確定）

A-4 で担当が無くなった4件について、オーナーが裁定した。原文:

> 1、これ明度でいい。暗くする＋共通のアイコンを個体詳細画面につけよう。その他状態異常全部に。
> 基本後半色がかなり混ざるので、色に関わる変更は一切なくしたい
> 2、これもOKだけど、個体詳細画面にアイコンつける・その他すべてアイコンをつける

## 決まったこと

| 件 | 盤面（シャーレ）での見え方 | 個体詳細での見え方 |
|---|---|---|
| 1. 体力／ケガ | **暗くする（明度）** | **アイコン** |
| 2. 恐怖（戦闘中） | **暗くする（明度）** | **アイコン** |
| 3. 疲れ／不満 | — | **アイコン** |
| 4. 局長の印／よそ者の印 | — | **アイコン** |
| その他すべての状態 | — | **アイコン** |

### 二層に分ける

- **盤面は「ただごとではない」ことだけ伝える。** 弱っている個体は暗くなる。内訳は言わない
- **内訳は個体詳細でアイコンが言う。** 何の状態かはここで名前が付く
- アイコンは**全状態に共通の1つの体系**として設計する。状態ごとに絵柄の作法がバラバラにならないこと

### 明度が戻ってきた理由（A-4 で撤廃したのに、なぜ）

A-4 で捨てたのは「明度＝**体力と年齢の両方**」という多重の意味づけ。
読めなかったのは、1つのチャンネルが2つのことを同時に言っていたから。
今回は **明度＝弱っている、それだけ**。年齢は大きさと年輪へ移した後なので衝突しない。
さらにアイコンが内訳を名指しするので、明度は「程度」だけを担えばよくなる。

## ★色に関する絶対規則（オーナー明言）

> 基本後半色がかなり混ざるので、色に関わる変更は一切なくしたい

**新しい符号化に色相・彩度を使ってはならない。** 理由は実装上も正しい：
血が混ざるほど色相は中間色へ寄り、後半はどの個体も似た濁った色になる。
その上に「赤なら危険」「緑なら健康」のような意味を載せると、後半に全部読めなくなる。

- 色相 = 血統。**これだけ。** 他の意味を載せない
- 彩度 = **使わない**（A-4 で撤廃済み）
- 明度 = 弱っているかどうか、それだけ（上記）
- 状態・所属・役割・警告は、**色ではなくアイコンと形と大きさで表す**

各班は、設計に「◯◯なら赤く」「危険は赤」の類を書かないこと。書いてあったら差し戻す。

## アイコンの作り方（描画班・キャラ班）

- **画像素材は使わない**（スプライト禁止の前提を継続）。
  個体詳細は DOM なので**コード内のインライン SVG**（パスを手で書く）で描く。
  盤面に出す必要が生じた場合は Canvas のパス描画で同じ形を再現できること
- 白黒（単色）で成立する形にする。**色で意味を分けない**（上記の絶対規則）
- 状態の一覧を先に確定してから絵柄を起こすこと。あとから足すと体系が崩れる
  （ケガ・恐怖・疲れ・不満・老い・よそ者・局長・妊娠・飢え・病…実装にあるものを全部洗い出す）

# A-7. 記号が盤面に入らない問題の裁定（2026-08-20 / オーナー確定）

突き合わせ班（`98-記号の突き合わせ.md`）が実測で出した2つの破綻に対する裁定。

## A-7-1. 細胞と年輪が読めない → **盤面に拡大（ズーム）を入れる**

### 何が壊れていたか（実測・20種×25世代／31,814体）

- 細胞が「数えられない」個体が **63.9%**、年輪4本が描けない個体が **98.5%**
- 人口の p90 = 120、最大 210。キャラ班の「117が sim の天井」は誤り。
  真の上限は `game/src/sim/constants.js:19` の `MAX_POP = 400`
- 世代の34%が人口84以上。そこでは細胞の上限が3個になり、**3人に2人が同じ絵**になる
- その「3個」という上限自体が、キャラ班が定めたすき間の下限（1.0px）を割っている
  （R=9/11/14 で 0.59/0.72/0.92px）。「3個までなら間隔が広い」は算数の間違い

### 決めたこと

盤面を拡大できるようにする。**引いた状態では数えられなくてよい。寄れば数えられる。**

### これで発生する作業（描画班・UI班）

1. **拡大・移動の操作**を1つ増やす。PC専用なので、ホイールで拡大／ドラッグで移動が自然。
   「1画面に1つの用件」との折り合いをどう付けるかを UI班が決める
   （拡大は"用件"ではなく"視点"なので抵触しない、という整理でよいかを含めて）
2. **座標変換と当たり判定の作り直し**。いまの `dish.js` は等倍前提。
   論理座標→画面座標の変換を1か所に集約し、ヒットテストも同じ変換を通す
3. **拡大率ごとの出し分け（LOD）を明文化する。**
   - 引いた状態（全体を見る）：色相・大きさ・暗さ・位置。細胞と年輪は「多い/少ない」の印象だけ
   - 中間：年輪が数えられる
   - 寄った状態：細胞が1個ずつ数えられる
   各段の切り替わり半径を、キャラ班の `scaleFor` を測り直したうえで決めること
4. **拡大しても盤面が消えないこと。** 過去に dt の発散で座標が -741045 まで飛んだ事故がある。
   変換行列を入れる以上、同じ事故が起きる面が増える。上限を切る規則を必ず書く
5. 個体詳細の肖像は 56px → 80px に上げる（キャラ班の要望どおり）。
   ここが年輪4本と細胞を同時に見せられる最小の場所

### 上限は下げない

`MAX_POP = 400` は触らない（A-6-2「sim は最小限」を維持）。読めない問題はズームで解く。

## A-7-2. 混血の見せ方 → **楔（扇形）で出す**

### 何が壊れていたか

キャラ班の実測：相手の色相が180度付近だと、**外来25%でも純血と完全に同じ色**になる。
120度の相手でも外来6.3%で色相のずれは3度。**中間色は混血を表せていない。**
v2 の主題（外来血が混ざるか混ざらないか）が、いちばん見せたい場面で見えない。

### 決めたこと

体の一部を扇形（楔）に区切り、**よその血の割合を面積で見せる**。

- 色相以外のチャンネルを1本も増やさないので、**色の絶対規則（A-5）に触れない**
- 混ざり具合が数値ではなく面積で読める
- 「よそ者本人」と「ここで生まれた混血の子」の区別は、
  本人だけ輪郭を破線にし、子は楔だけで読ませる（キャラ班の案を採用）

## A-7-3. こちらで決めた小さいもの（異論があれば言ってください）

キャラ班が挙げた残りの未決のうち、実装の事実から答えが1つに決まるもの：

- **妊娠のアイコンは作らない。** 実装に妊娠している期間が無い（`world.js:773` の `birth()` で
  出産が一瞬で終わる）。存在しない状態の絵は描かない。代わりに「子がいる」を出す
