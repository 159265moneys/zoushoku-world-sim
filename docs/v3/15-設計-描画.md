## 0. 5行でいうと

1. **個体の絵のコストは、弧（`arc`）の本数にきれいに比例する。1弧 2.0〜2.5μs。**
   だから予算は「1体あたり何μs」ではなく「**1フレームの総弧数 1800本**」で持つ。数えれば誰でも検算できる。
2. **細胞方式は予算に収まる。** sim の実測分布どおりに混ぜると 1体あたり平均 5.97本。
   人口150で総弧数 895本＝**1.91ms**（予算 4.0ms）。最悪の個体ばかりの人口150でも 3.4ms。

4. **背景マップを毎フレーム描いてはいけない**（28.2ms）。canvas を3枚重ねる（0.81ms）。ここは旧版から変えない。
5. **ばねは固定ステップで積分する。** 過去の座標 −741045 は dt が **27.07秒**を超えて数学的に発散した値そのもの。

## 1. 実測

測定台は2つある。**両方とも消さないこと。**

| 台 | 何を測る | 起動 |
|---|---|---|
| `game/test/bench-draw.html` | 背景マップの出し方、旧記号、DOM の肖像、禁止技の値段 | `cd game && python3 -m http.server 8777` → `/test/bench-draw.html` |
| `game/test/bench-cells.html` | **A-4 の新記号（膜・年輪・細胞）のコストと幾何** | 同上 → `/test/bench-cells.html` |

以下の数字は Chrome / `devicePixelRatio` 2 / 盤面 **900×744 論理px**（＝実 1800×1488px。X-06 の裁定）で取った。
canvas 1枚の VRAM は **10.2MB**、3枚で 30.6MB。

### 1-1. 測り方の罠（2つある。両方踏むと10倍まちがえる）

**Canvas2D は遅延実行される。** `fill()` を呼んだ時点ではコマンドを記録するだけで、絵が実際に作られるのは後。

| 測り方 | 出る値（新記号・人口150） | 何を測っているか |
|---|---:|---|
| そのまま挟んで測る | 0.19 ms | **JS がコマンドを記録する時間だけ。嘘** |
| 200回まとめて回して最後に1回だけ同期 | 0.19 ms | **同じく嘘。**捨てられるフレームの塗りは GPU が省略する |
| **1フレームごとに `getImageData(0,0,1,1)` で同期を強制** | **1.91 ms** | **本当。**塗りまで終わらせている |

**10倍ちがう。** 旧版が「まとめて測ると速く見える」罠だけを書いていたので、こちらで踏み直して両方書いた。
`bench-cells.html` の `timedThroughput()` は**わざと間違った測り方**を残してある（比較用）。
数字を引用するときは、必ず `timed()`（毎フレーム同期）のほうを使うこと。

> 注：毎フレームの同期は GPU のパイプラインを切るので、**実測値は上限寄りに出る**。
> 実際のゲームは1フレームぶんの仕事しかしないので、ここに書いた値より速くなることはあっても遅くなることはない。
> 安全側なので、この測り方でよい。

### 1-5. 焼いて `drawImage` は、盤面では速くならない

旧版は「16枚のスプライトを焼いて貼ると 5.9μs／直接パス 4.1μs より遅い」と測っていた。
**新記号（弧11本）でも結論は変わらなかった。**

| 人口150・R=9 | ms/フレーム | 1体あたり |
|---|---:|---:|
| 直接パスで描く（年輪3・細胞7） | 3.00 | **20.0μs** |
| 焼いた絵を `drawImage`（150枚バラバラ） | 4.18〜9.15 | **27.9〜61.0μs** |
| 同上 ＋ 弱りの黒円 | 4.34 | 28.9μs |
| （参考）1体ぶんを焼くコスト | — | 11〜14μs／回 |

**実行のたびに 4.2ms 〜 9.1ms とぶれた。** 直接パス（3.00 / 3.10 / 3.23ms）はぶれていない。
`drawImage` は canvas→canvas のテクスチャ転送を挟むので、Chrome の合成の都合に左右される。
旧版も背景の B 方式で同じぶれを注記している。**ぶれる最適化は、速くても採らない。**

さらに2つ、質の問題がある。

- 個体は毎フレーム小数座標で動く。焼いた絵を小数位置に貼ると**再標本化でにじむ**。直接パスは常にくっきり出る
- 焼くとキャッシュの管理（焼き直しの条件・上限・失効）が要る。**効かない最適化のためにバグの温床を増やすことになる**

→ **決定：盤面（actors レイヤ）では焼かない。直接パスで描く。**
　焼く設計そのものは捨てない。**DOM の肖像では焼くのが正しい**（§13）。盤面用の非常口としても条件つきで残す（§13-3）。

### 2-2. 体の中の割り当て（先に決めないと3つとも読めなくなる）

年輪・細胞・血すじは**全部が体の内側**を使う。取り合いになるので、半径で領域を分ける。
以下は R ＝ 描画半径（論理px）。

```
  0    〜 0.50R   核。細胞（粒）だけが入る
  0.50 〜 0.58R   すきま。何も描かない
  0.58 〜 0.97R   帯。年輪（同心の細線）だけが入る
  0.97R           膜。輪郭線 1本（lineWidth 1.0）
```

- **塗り**（＝血すじの色相、混血なら楔）は円ぜんたい。年輪と細胞はその上に載る
- **年輪の線幅 0.8px、輪と輪の間隔は最低 1.5px**（論理px。dpr2 で実 3.0px）
- **細胞の色は、本体色を暗くしたもの**（同じ色相・同じ彩度・明度だけ下げる）。
  別の色相を使わないこと。使うと「色相＝血すじ」が壊れる

**ハロー（ホバー／選択）は膜の外側**に描く二重円。半径 R+4（ホバー）／R+6（選択）。
選択は `--ind`（個体の青）、ホバーは薄い白。**これは状態ではなく操作の反応なので、色を使ってよい唯一の例外**（`REQUIREMENTS` 6-1）。

#### 細胞の詰め方（円の中に等円を詰める既知の最密解を使う）

| 細胞の数 n | 半径比 `PACK[n]`（核の半径を1とする） | 中心からの距離 | 配置 |
|---:|---:|---:|---|
| 1 | 1.0000 | 0 | 中心に1つ |
| 2 | 0.5000 | 0.5000 | 左右 |
| 3 | 0.4641 | 0.5359 | 正三角 |
| 4 | 0.4142 | 0.5858 | 正方 |
| 5 | 0.3702 | 0.6298 | 正五角 |
| 6 | 0.3333 | 0.6667 | 正六角 |
| 7 | 0.3333 | 0.6667 | 正六角 ＋ 中心に1つ |

```js
細胞1個の半径 rc = 0.50R × PACK[n] × 0.86      // 0.86 は粒どうしを触れさせないための隙間
```

**粒が潰れない下限：`rc ≥ 1.10`（論理px。dpr2 で実画素の直径 4.4px）。**
これを下回ると隣の粒とにじんでつながり、**数えられなくなる**。

|---:|---:|---:|---:|---:|---:|---:|---:|

| 7.1（2歳・base10） | 3.05 | 1.53 | 1.42 | 1.26 | 1.13 | 1.02 | 1.02 |
| **10.0（大人・base10）** | 4.30 | 2.15 | 2.00 | 1.78 | 1.59 | **1.43** | **1.43** |

| 26.0（肖像 52px） | 11.18 | 5.59 | 5.19 | 4.63 | 4.14 | 3.72 | 3.72 |

| 数えたい細胞の数 | 要る R |
|---:|---:|
| 7個・6個 | **7.67** |

| 4個 | 6.18 |

### 2-3. 細胞の数 ＝ 熟練

（旧 `training()` は5軸の平均。`color.js:73-78`。**捨てる。**

#### 段の切り方は「何世代その仕事をしたか」で切る

練度の伸びは `world.js:283` の飽和曲線で、環境係数がおよそ1のとき1世代（12tick）でこう進む。

```
p.skills[sk] = cur + rate × envCoef × (1 - cur) / TICKS_PER_GEN × 4
→ 1世代後 0.483 / 2世代 0.733 / 3世代 0.862 / 4世代 0.929 / 5世代 0.963 / 6世代 0.981
```

**練度の値は、もともと「世代の階段」になっている。**（実測の分布が二峰だったのはこのため）
だから境目は各段の中点に置く。こうすると **細胞が1個増える＝もう1世代その仕事をした**、が文字どおり成立する。

| 細胞 | `max(skills)` の範囲 | 意味 | 実測の割合 |
|---:|---|---|---:|
| 1 | < 0.24 | まだ働いていない | 38.4% |
| 2 | 0.24 〜 0.61 | 1世代ぶん | 13.1% |
| 3 | 0.61 〜 0.80 | 2世代 | 1.8% |
| 4 | 0.80 〜 0.895 | 3世代 | 11.9% |
| 5 | 0.895 〜 0.946 | 4世代 | 12.4% |
| 6 | 0.946 〜 0.972 | 5世代 | 9.3% |
| 7 | ≥ 0.972 | 6世代以上 | 13.1% |

```js
const CELL_STEP = [0.24, 0.61, 0.80, 0.895, 0.946, 0.972];
/** 細胞の数 1..7 */
export function cellCount(ind) {
  let top = 0;
  for (const k of SKILLS) { const v = ind.skills?.[k] ?? 0; if (v > top) top = v; }
  let n = 1;
  for (const t of CELL_STEP) if (top >= t) n++;
  return n;

```

**7個で頭打ちにする理由：** 人が一目で数えられるのは7個までで、それ以上は「多い」としか読めない。
細胞を8個以上にするくらいなら、頭打ちにして「これ以上は個体詳細で読む」ほうが正直である。

### 2-4. 年輪 ＝ 年齢

**大きさと年輪は、どちらも年齢を表す。重ねてよい。** 木の年輪がまさにそうなっているし、
「太い＝古い」と「輪が多い＝古い」が同じ向きを指すので、片方が読めなくても意味が壊れない。
役割は分けてある。

- **大きさ**＝**育ち**。`radiusOf()` は `age/5` で頭打ちになる（`color.js:104`）。子どもか大人かが分かる
- **年輪**＝**積み重ねた歳**。大人になってからも増え続ける。**老いはここでしか読めない**

段は**絶対年齢**で切る。**`age ÷ 寿命` では切らないこと。**
実測で `age/寿命` は p99.9 でも **0.474**——**誰ひとり寿命の半分まで生きない**。
割合で切ると上半分の段が永久に空になり、「老い」が一度も画面に出ない。

| 年輪 | 年齢 | 実測の割合 | 盤面 | 肖像 |
|---:|---|---:|---:|---:|
| 0本 | 0〜1（子ども。`ADULT_AGE = 2`） | 25.9% | 0 | 0 |
| 1本 | 2〜3 | 24.7% | 1 | 1 |
| 2本 | 4〜6 | 31.9% | 2 | 2 |
| 3本 | 7〜9 | 15.3% | 3 | 3 |
| 4本 | 10以上 | 2.1% | 3（頭打ち） | 4 |

```js
const RING_AGE = [2, 4, 7, 10];
/** 年輪の本数 0..4 */
export function ringCount(ind) {
  let n = 0;
  for (const t of RING_AGE) if ((ind.age ?? 0) >= t) n++;
  return n;
}
```

**5本目・6本目は作らない。** 40種×40世代の実測で **0.0%**。誰もそこまで生きない。
存在しない段のために幾何を苦しくする理由がない。もし将来 sim が長寿を許したら、そのとき足す。

**子どもは年輪0本・細胞1個なので、つるんとした丸になる。**
これは狙ってそうしている。**まだ何も刻まれていない**という読みがそのまま絵になる。

#### 盤面で頭打ちになる件

年輪3本には R ≥ 9.74 が要り、4本には R ≥ 13.59 が要る（§2-2）。base の上限は 13 なので、
**盤面では 4本目が出ない。**該当するのは年齢10以上＝実測 **2.1%**。
そのときは個体詳細（肖像 R=26）が本当の本数を出す。A-5 の二層（盤面は程度・詳細は内訳）と同じ扱いで統一する。

**幾何と意味の向きが一致していることに注意。**
年輪が多い個体は年齢が高く、年齢が高い個体は大きい（＝帯が広い）。
「本数が増えると入らなくなる」という失敗は構造的に起きにくい。

### 2-5. 数えられなくなったときの規則

A-4 の宿題：「数えられない密度になったら別の出し方に切り替える規則を書くこと」。

**答え：記号は切り替えない。段を粗くする。**

```
細胞も年輪も、入る本数まで「段の刻み」を粗くする。丸だけが残り、意味の軸は変わらない。
```

| R | 細胞の段 | 年輪の段 |
|---|---|---|
| R ≥ 9.74 | 7段（1〜7個） | 4段（0〜3本） |
| 7.67 ≤ R < 9.74 | 7段（1〜7個） | 3段（0〜2本） |
| 6.18 ≤ R < 7.67 | 4段（1・2・3・4個） | 3段（0〜2本） |
| 5.12 ≤ R < 6.18 | 2段（1個・2個） | 3段（0〜2本） |
| R < 5.12 | 1段（＝盤面に熟練を出さない） | 2段（0〜1本） |

段を粗くするときは `Math.round(段 × 出せる段数 / 元の段数)` で丸める。**単調性が保たれること**（歳を取ると本数が減る、が絶対に起きないこと）を受け入れ条件に入れる（E-11）。

#### なぜ「別の記号」に切り替えないか

旧案には「数えられなくなったら段階リング表示に切り替える」という書き方があった。**採らない。**
盤面には大きい個体と小さい個体が同時にいる。記号を大きさで切り替えると、
**同じ画面の中に2つの読み方が同時に存在する**ことになり、どちらも読めなくなる。
段が粗いだけなら、読み方は1つのままである。

#### 段が切り替わるとき、絵が飛ぶ問題

R は人口で変わる（`base`）。人口が1人増えたときに全員の細胞数が一斉に変わると、盤面が「バグった」ように見える。

→ **`base` は段でしか動かさない**（`REQUIREMENTS` 6-1 と同じ指定）。
　連続に変えると毎世代ぬるぬる動く。段にすれば、切り替わる回数がゲーム全体で数回に収まる。

```js
// 人口 → base。段でしか動かない。
const BASE_LADDER = [[40, 13.0], [60, 11.5], [999, 10.0]];   // pop 以下なら その base
```

### 2-6. 描画半径の下限（14 への要求）★

14 §5.3 の式は `base = clamp(13 - pop×0.05, 5.0, 13) × clamp(R̄/310, 0.72, 1.15)`。
**下限 5.0 では A-4 の記号が1つも読めない。**

| 人口 | 旧式の base | 大人の R | 細胞 | 年輪 |
|---:|---:|---:|---|---|
| 10 | 12.5 | 12.5 | 7個まで ○ | 3本まで ○ |
| 100 | 8.0 | 8.0 | 7個まで ○ | 2本まで（3本 ✕） |
| 150 | 5.5 | 5.5 | **2個まで ✕** | 2本まで |
| 400 | 5.0 | 5.0 | **1個 ✕** | 1本 |

**→ 描画班から 14 への要求：`base` の下限を 5.0 から 10.0 に上げること。**

面積が足りるかを確かめた。R=10 なら直径 20px、14 §5.2 の「せまい」判定は `pitch < 1.9×dot` なので pitch は 38px。
六方格子で1人あたり `(√3/2) × 38² = 1,250px²`。

| 人口 | 要る面積 | 盤面 900×744 = 669,600px² のうち |
|---:|---:|---:|
| 100（P2 の天井・R-301） | 125,000 px² | **19%** |
| 150 | 187,500 px² | **28%** |
| 173（実測の最大） | 216,000 px² | **32%** |

**余る。** 詰まるのは面積ではなく、区画ごとの席の割り当て（14 §5）である。
そちらで足りなくなったときは、**細胞と年輪を削るのではなく、区画の面積配分を見直すこと**。
A-4 が「数えられることが生命線」と言っている以上、削る順番はこちらが後ろになる。

（`clamp(R̄/310, 0.72, 1.15)` の窓サイズ係数は X-06 で盤面が 900×744 に確定したので、
　14 が実ピクセルで取り直す。下限 10.0 は**係数を掛けた後の値**に対して要求する）

### 2-7. 明度 ＝ 弱っている、それだけ

#### いまの実装の何が壊れているか

```js
// color.js:81-89
let li = 70 - 42 * t;              // ← 年齢
if (ind.wounded) li -= 9;          // ← ケガ
li -= 7 * clamp(ind.fatigue ?? 0); // ← 疲れ
```

**3つの意味が1つの数に足しこまれている。**
「若くて疲れている個体」と「中年で元気な個体」がまったく同じ明度になる。区別する手段が画面にない。
A-4 が「明度が意味不明」と言ったのはこれで、A-5 が明度を戻したのは
**年齢が大きさと年輪へ移った後なら、明度は1つのことだけ言える**からである。

#### 直し方：入力を1つにする

```js
/**
 * 弱り 0..1。0＝元気、1＝いまにも倒れる。
 * ★この関数に年齢・練度・生死・血統を足さないこと。足した瞬間に A-5 の裁定が壊れる。
 * ★足し算ではなく max を取る。足すと「軽い不調が3つ」で「瀕死」と同じ暗さになる。
 */
export function frailty(ind) {
  let f = 0;
  if (ind.wounded) f = Math.max(f, 0.55);                       // model.js:59 / battle.js:378
  f = Math.max(f, 0.45 * clamp(ind.fatigue ?? 0));              // model.js:58 / world.js:194
  if (Number.isFinite(ind.fear)) f = Math.max(f, 0.70 * clamp(ind.fear));  // 戦闘の中だけ（§2-7 末尾）
  return clamp(f);
}
```

盤面での効かせ方は**焼き直しの要らない形**にする（§13 のキャッシュ設計と噛み合わせるため）。

```js
// 本体を描いたあと、同じ半径の黒円を alpha で重ねる。弧1本ぶん（2.2μs）
if (f > 0) {
  g.beginPath(); g.arc(x, y, R, 0, TAU);
  g.fillStyle = `rgba(0,0,0,${(0.55 * f).toFixed(3)})`;
  g.fill();
}
```

- 最大でも 55% までしか暗くしない。**真っ黒にすると色相（＝血すじ）が読めなくなる**
- 黒を重ねるので、**どの色相でも同じだけ暗くなる**（「弱り」の意味が色相によってぶれない）
- **年輪も細胞も一緒に暗くなる。**これは正しい。弱っているのは個体ぜんたいだから

#### 「恐怖」は盤面には出せない。出すと嘘になる

A-5 は「2. 恐怖（戦闘中）→ 盤面で暗くする」と裁定している。実装を確認した結果：

- **`sim` には `fear` という値が存在しない。** `game/src/sim/` 全体を検索して、個体にも戦闘ユニットにも `fear` は無い
- 戦闘の恐怖は **UI が導出している**（`adapter.js:241`
  `f.fear = u.dead ? 1 : clamp((1 - dst.cohesion) * (1.35 - nerve) + (u.fled ? 0.7 : 0))`）。
  これは**戦闘モーダルの中の `f`（ユニット）にだけ載る**値で、`world.people` の個体には載らない
- `color.js:110` の `if (Number.isFinite(ind.fear))` は、**盤面からは一度も真にならない**。
  実際に走るのは下の `color.js:112-116` で、`world.morale` と `world.food` から
  **UI が独自に恐怖を発明している**（sim にその値は無い）

**決定：**

1. **平時の `fearOf()` は捨てる。** 存在しない量を画面に出している（R-009「事実は常に正確に見える」違反）
2. **盤面の弱り＝ケガ と 疲れ の2つだけ。** どちらも sim が実際に持っている
3. **恐怖は、恐怖が実在する場所——戦闘の描画——でだけ効かせる。**
   `frailty()` は `ind.fear` が有限のときだけそれを読む（＝戦闘ユニットを渡したときだけ効く）ので、
   関数はそのままで両方に使える。A-5 の裁定は満たされる

### 2-8. 死・退場（彩度を動かしてよい唯一の場所）

彩度は A-4 で撤廃したが、**生存／死亡の区別にだけは使ってよい**（`REQUIREMENTS` 6-1）。

### 2-9. 1体を描く（擬似コード）

```js
// ============================================================ src/ui/actor.js
const TAU = Math.PI * 2;
const PACK  = [0, 1.0000, 0.5000, 0.4641, 0.4142, 0.3702, 0.3333, 0.3333];
const RINGD = [0, 0.0000, 0.5000, 0.5359, 0.5858, 0.6298, 0.6667, 0.6667];
const CORE = 0.50, BAND_IN = 0.58, BAND_OUT = 0.97, GAP = 0.86;
const RC_MIN = 1.10;            // 粒が潰れない下限（論理px）
const RING_W = 0.8, RING_PITCH = 1.5;

// 細胞の単位座標を一度だけ作る（毎フレーム作らない）
const UNITS = [];
for (let n = 1; n <= 7; n++) {
  const a = [];
  if (n === 1 || n === 7) a.push([0, 0]);
  const ring = n === 7 ? 6 : (n === 1 ? 0 : n);
  for (let i = 0; i < ring; i++) {
    const th = -Math.PI / 2 + (i / ring) * TAU;
    a.push([Math.cos(th) * RINGD[n], Math.sin(th) * RINGD[n]]);
  }
  UNITS[n] = a;
}

/** R に入る細胞の最大数（§2-5 の段を粗くする規則） */
function cellsThatFit(R) {
  for (let n = 7; n >= 2; n--) if (R * CORE * PACK[n] * GAP >= RC_MIN) return n;
  return 1;
}
/** R に入る年輪の最大本数 */
function ringsThatFit(R) {
  return Math.max(1, Math.floor((R * (BAND_OUT - BAND_IN) - RING_W) / RING_PITCH) + 1);
}
/** 段を粗くする。単調性を壊さない（E-11） */
function coarsen(step, maxStep, fitMax) {
  if (fitMax >= maxStep) return step;
  return Math.round(step * fitMax / maxStep);
}

/**
 * 1体を描く。弧の本数 = 1（膜）+ 年輪 + 細胞 + 弱り。予算は §10-1。
 * st = { cells:1..7, rings:0..4, frailty:0..1, hover, selected, fadeIn, fadeOut, lod, fill, ink }
 *   fill = 本体色（血すじ）／ ink = 本体色を暗くした色（細胞と年輪に使う。別の色相を持ち込まない）
 */
export function drawActor(g, x, y, R, st) {
  if (st.selected || st.hover) {                       // ハロー（操作の反応。色を使ってよい）
    g.beginPath(); g.arc(x, y, R + (st.selected ? 6 : 4), 0, TAU);
    g.fillStyle = st.selected ? 'rgba(120,168,255,0.30)' : 'rgba(200,215,255,0.16)';
    g.fill();
  }

  g.beginPath(); g.arc(x, y, R, 0, TAU);               // 膜＋塗り（血すじ）
  g.fillStyle = st.fill; g.fill();

  if (st.lod < 2) {                                     // 年輪（§10-3 の第1段で落ちる）
    const nr = coarsen(st.rings, 4, ringsThatFit(R));
    if (nr > 0) {
      const bIn = R * BAND_IN, bOut = R * BAND_OUT;
      const step = nr > 1 ? (bOut - bIn) / (nr - 1) : 0;
      g.strokeStyle = st.ink; g.lineWidth = RING_W;
      for (let i = 0; i < nr; i++) { g.beginPath(); g.arc(x, y, bIn + step * i, 0, TAU); g.stroke(); }
    }
  }

  const nc = coarsen(st.cells, 7, cellsThatFit(R));     // 細胞（★絶対に落とさない。§10-3）
  const Rc = R * CORE, rc = Rc * PACK[nc] * GAP;
  g.fillStyle = st.ink;
  for (const [ux, uy] of UNITS[nc]) {
    g.beginPath(); g.arc(x + ux * Rc, y + uy * Rc, rc, 0, TAU); g.fill();
  }

  if (st.frailty > 0) {                                 // 弱り（§2-7）
    g.beginPath(); g.arc(x, y, R, 0, TAU);
    g.fillStyle = `rgba(0,0,0,${(0.55 * st.frailty).toFixed(3)})`; g.fill();
  }
}
```

**`st` は呼ぶ側（`dish.js`）が作る。`drawActor` は `world` を読まない。**
退場中の個体は `world.people` から消えていて `p.skills` も `p.lineage` も引けないため、
必要な値は消える前の最後のフレームでコピーしておく（§9-2）。

### 3-2. 1つの `d` 文字列を、DOM と Canvas の両方で使う

A-5 の指定：画像素材は使わない／個体詳細は DOM なのでインライン SVG／盤面に出すなら Canvas のパスで同じ形。

**答え：形の定義を1か所（`d` 文字列）だけにして、2つの描き手に渡す。**
`Path2D` のコンストラクタは **SVG のパスデータ文字列をそのまま受け取れる**。実機で確かめた（`bench-cells.html` §5）。

```js
// ============================================================ src/ui/icons.js
// 24×24 のグリッド。ここが唯一の形の定義。SVG と Canvas がこの1本を共有する。
export const ICON = {
  wounded: 'M4 13 L9 13 L11 8 L14 17 L16 13 L20 13 ...',   // 心電図が落ちる形
  fatigue: 'M6 5 H18 L13 12 L18 19 H6 L11 12 Z',           // 砂時計
  // …（15個）
};

// DOM 側：個体詳細のパネルに置く
export function iconEl(id, title) {
  const s = document.createElementNS('http://www.w3.org/2000/svg', 'svg');
  s.setAttribute('viewBox', '0 0 24 24');
  s.setAttribute('class', 'ico');
  s.setAttribute('role', 'img');
  s.setAttribute('aria-label', title);
  const p = document.createElementNS('http://www.w3.org/2000/svg', 'path');
  p.setAttribute('d', ICON[id]);
  p.setAttribute('fill', 'currentColor');   // ★色は CSS の currentColor 1つだけ
  s.appendChild(p);
  return s;
}

// Canvas 側：モジュール読み込み時に一度だけ作る。毎フレーム new しない
const PATHS = {};
for (const k in ICON) PATHS[k] = new Path2D(ICON[k]);

/** (x,y) を中心に size px で描く。size は 24 に対する拡大率で効く */
export function iconPath(g, id, x, y, size, style) {
  g.save();
  g.translate(x - size / 2, y - size / 2);
  g.scale(size / 24, size / 24);
  g.fillStyle = style;
  g.fill(PATHS[id]);        // ★ fill-rule は既定の nonzero。SVG の既定と同じ
  g.restore();
}
```

実測（人口150ぶん＝150回）：

| | ms/150回 | 1回 |
|---|---:|---:|
| `new Path2D(d)` を毎回作る | 0.305 | 2.03μs |
| 1回作って使い回す | 0.263 | 1.75μs |

**差は小さいが、毎回作る理由が1つも無い。** モジュール読み込み時に作ること。
`save`/`restore` は 3.3μs（§1-7）。アイコンは盤面に大量に出るものではないので許容する。

### 3-3. 絵柄の作法（15個すべてが従うこと）

| 決めごと | 値 | なぜ |
|---|---|---|
| グリッド | **24×24**、外周2pxは余白（実効 20×20） | 小さくしたとき端が切れない |
| 色 | **`currentColor` 1色だけ。**塗りのみ | A-5「白黒で成立する形」／色の絶対規則 |
| 線 | **`stroke` を使わない。**線に見せたい部分も塗りの帯で描く | `stroke-width` や `linecap` は `d` に入らない。Canvas と SVG で形が変わる |
| 太さ | 帯の太さは **2.0**（24グリッド上） | 12px に縮めても 1px 残る |
| 穴 | 外側と内側で**回転の向きを逆にする**（nonzero で抜ける） | **`fill-rule: evenodd` を使わないこと。**Canvas の `fill(path)` の既定と揃えるため |
| コマンド | `M L H V C Q A Z` と数字だけ。`d` 以外の属性に意味を持たせない | 両方の描き手が読める部分集合 |
| 最小表示 | **14px 以上**で使う | 20×20 の絵を 14px に縮めると細部が 1px 未満になる |
| 意味の伝え方 | **形だけ。**同じ絵柄を色違いで別の意味にしない | 色の絶対規則 |

**個体詳細での置き方**：アイコンと**名前**を必ず並べる（アイコン単独で置かない）。
初見のプレイヤーはアイコンの意味を知らない。名前があれば、2回目からはアイコンだけで読めるようになる。
名前は用語班（11）の辞書項目にして、ホバー説明を付ける（R-933）。

### 3-4. 盤面にアイコンを出す場合

**既定では出さない。** A-5 の二層（盤面は程度だけ、内訳は個体詳細）に従う。

盤面に出してよいのは**個体の状態ではないもの**だけ、という線を引く。

| 出してよい | 例 |
|---|---|
| 場所に付くもの | 門・蔵・訓練場の印（動かない。数が増えない） |
| 世界に1つしかないもの | 捕虜が門の外で待っている印 |

| 出さない | なぜ |
|---|---|
| ケガ・疲れ・恨み・老いなど個体の状態 | 人口150で150個のアイコンが動き回る。**盤面が読めなくなる**。A-5 が二層に分けた理由そのもの |
| 局長の印 | 3人しかいない。探す用件が無い（`REQUIREMENTS` 6-1） |
| よそから来た人の印 | 色相で読める（それが看板） |

出すときは `iconPath()` を使い、**サイズ 14px 以上**、**actors レイヤの個体より後**に描く。

### 4-2. 民心 ＝ 中心の囲いの線が「ほどける」

**事実の確認**（推測しないために実装を読んだ）：

- `w.morale` は `[C.MORALE_FLOOR, 1]` の範囲。`MORALE_FLOOR = 0.02`（`constants.js:109`）
- 更新は `w.morale += (target - w.morale) * 0.25`（`world.js:385`）。**1世代で最大25%しか動かない**ので、
  補間しなくても飛ばない。それでも段差は出るので 0.6秒で追わせる

**出し方**：中心の囲い（多角形。辺の数＝発展段階、14 §6）の**各辺を、中央から外へ削る**。

```js
// 辺の長さを Lseg とすると、実際に描くのは中央の Lseg × morale ぶんだけ。
// 民心 1.00 → 閉じた多角形     民心 0.60 → 各辺の中央6割だけ残り、角が離れて見える
// 民心 0.20 → 短い線が浮いているだけ    民心 0.02 → ほとんど消える
const keep = clamp(shown.morale, 0.02, 1);
g.setLineDash([Lseg * keep, Lseg]);          // 実線ぶん / 間隔ぶん
g.lineDashOffset = -Lseg * (1 - keep) / 2;   // 中央に寄せる
```

- **色を1つも使わない。** 線の色は地形と同じ無彩色のまま
- **「囲いがほどけている＝国のまとまりが失われている」**が一目で読める
- 角（頂点）が最後まで残るので、**辺の数（＝発展段階）は民心が低くても数えられる**。
  2つの意味が同じ線に載っているが、**片方は「本数」、もう片方は「つながり」**なので競合しない
- `shown.morale` は表示用の追従値。`shown += (world.morale - shown) × (1 - exp(-h/0.2))` で 0.6秒程度で追う

**pulse との関係**：民心が世代境界で大きく動いたときは §4-4 の `pulse` を1つ使う。

### 4-3. 国への恨み ＝ 囲いから外へ伸びる「ひび」の本数

**事実の確認**：

- `w.regimeGrudge` は `p.regimeGrudge`（各人 0〜1）の**平均**（`world.js:373-386`）。**範囲は 0〜1**
- 一揆は `pressure = 平均 × (1 - morale) × (1 + 扇動者×0.35) × 抑圧` が **0.22 以上**で抽選される（`world.js:931-932`）
- **`report.js:118` の `if (w.regimeGrudge > 3)` は永久に偽。**平均値なので 1 を超えない。
  「不満を口にする者が増えています」は**一度も出ない死んだ分岐**である。UI班へ申し送り（§15-4）

**出し方**：囲いの**頂点から外向きに、短い線（ひび）を生やす**。

```
本数   n = Math.round(regimeGrudge × 8)        // 0〜8本。数えられる
長さ   L = 囲いの半径 × (0.10 + 0.45 × regimeGrudge)
線幅   1.2px、無彩色（地形の線と同じ）、ひびなので直線ではなく2〜3節の折れ線
起点   囲いの頂点（辺の数だけある）。足りなければ辺の中点も使う
向き   外向き。折れの角度は new RNG(world.seed ^ 0x9017) で決める（毎フレーム同じ形になる）
```

**一揆が近いことを、形で言う。**

```
pressure = regimeGrudge × (1 - morale) が 0.22 を超えたら（＝一揆の抽選が始まる水準）
  → ひびの先端が「囲いの外周（村はずれの破線）」に届く長さまで伸びる
```

これは A-1 の2番目「変化を、変化として見えること」への答えでもある。
**数が増えるのが見え、届くかどうかで危険が読める。**「あと少し」が絵に出る。

- **色を1つも使わない**
- 民心（ほどけ）と恨み（ひび）は**同じ場所の別のチャンネル**（つながり／付き出し）なので混ざらない
- レイヤは **field**（世代ごとに変わる。terrain の 28ms を払わせない）

**まだ出さないもの**：`w.fear`（粛清の抑圧。`world.js:929`）は実装にあるが、**盤面には出さない**。
1つの場所に3つ載せると読めなくなる。個体詳細と報告で数字＋説明にする。**未決ではなく、出さないと決めた。**

### 4-4. 「変化を、変化として見せる」共通の仕組み

盤面には、もともと変化が変化として出るものが3つある（§4-1）。
**三角の流れ**／**耕地の伸び縮み**／**席の移動**。これらは A-1 を追加の演出なしで満たす。

足りないのは「世代境界で、ある量が段差で変わったとき」。共通の道具を1つだけ用意する。

```js
/** 何かが変わったことを 1.2 秒だけ強調する。全チャンネル共通。 */
pulse(key, dir)     // dir: +1 増えた / -1 減った
// 効果：対象の輪郭の太さを 1.2 秒かけて戻す。
//   増えた → 輪郭が外へ 2.5px 太って戻る
//   減った → 輪郭が内へ 2.5px 細って戻る
```

**旧版は「増＝緑／減＝橙」と色を使っていた。捨てた。**（色の絶対規則）
向きは**外に太る／内に細る**の形だけで出す。モノクロでも読める。

**規則（守らないと画面が読めなくなる）**

1. **同時に走ってよい pulse は3つまで。** 4つ目からは古いものを打ち切る。全部光ったら何も光っていないのと同じ
2. **点滅（周期的に明滅するもの）は画面に1つまで。** いまの候補は「門の明滅（捕虜待ち）」だけ。
   `style.css` の `.btn.war` も `animation: pulse` で明滅している。**盤面と同時に光らせない**
3. **色で意味を伝えない。** 増減は形（太る／細る）だけで出す
4. **量を意味しない飾りを増やさない**（14 §0-3 と同じ）。木や杭は固定の風景であって、数ではない

### 4-5. 数字を出すなら意味を添える（A-1 の3番目）

担当は用語班（11）とデザイン班だが、**受け皿は描画班が作る**。

- 盤面の上の DOM オーバーレイ（§5）に、区画名・蔵・村はずれの境のラベルを置く
- ラベルは `<span class="tip" data-term="field">` の形にして、**用語班の辞書と同じツールチップ機構に乗せる**（R-933）
- **canvas に文字を描くと、そこにホバー説明を付けられない。** これが「文字は DOM」の最大の理由（§5-2）

## 5. レイヤ構成

`#stage` の中に canvas を3枚重ねる。いちばん上に DOM のオーバーレイを1枚。

```
#stage  (position:relative)
├── canvas#layer-terrain   z-index:1   地形     ← 焼き直しは数世代に1回
├── canvas#layer-field     z-index:2   地物・資源・民心・恨み ← dirty のときだけ
├── canvas#layer-actors    z-index:3   個体・流れ・装飾 ← 毎フレーム
└── div#layer-overlay      z-index:4   文字・名札・ツールチップ ← DOM
    └── (既存の #strains / #legend / #toast / #indpanel はこの上)
```

### 5-1. 14 の描画順（§10.2）を、そのままこの3枚に割り振れる

**絵も順番も1つも変えない。** どの canvas に置くかだけが変わる。

| 14 の描画順 | 置く場所 | 描き直す条件 | 実測 |
|---|---|---|---|
| 1. `clearRect` | 各レイヤが自分の分だけ | — | 0.19ms |
| 2. 背景（地面・耕地幅・木/岩/小屋・道・外周・門の柱・村はずれの破線） | **terrain** | キャッシュキーが変わったとき（§6-4） | 28ms／回 |
| 区画の点灯／沈み・村はずれの開閉（**補間中だけ毎フレーム**） | **field** | 補間中のみ。止まったら固定 | 小 |
| 3. 蔵ゲージ | **field** | tick ごと | 小 |
| 3b. **民心のほどけ・恨みのひび**（§4-2・§4-3） | **field** | 世代ごと＋追従の補間中 | 小 |
| 4. 資源の三角（流れ） | **actors** | 毎フレーム | 48粒で 0.1ms 未満 |
| 5. 個体：村はずれ → まんなかの順、選択中は最後 | **actors** | 毎フレーム | 人口150で **1.91ms** |
| 6. 区画ラベル | **overlay（DOM）** | 区画の人数が変わったとき | 0 |
| 7. 選択区画の輪郭・門の明滅 | **actors**（個体の後に描く） | 毎フレーム | 小 |
| 8. ホバー名札 | **overlay（DOM）** | ホバーが変わったとき | 0 |

**ここが噛み合う理由：** 14 の順番で「個体より上」に来るのは 6（ラベル）と 7（選択輪郭・門）だけ。
7 は毎フレーム描くものなので actors に置いて個体の後に描けばよい。6 は DOM に上げれば全 canvas より上に来る。
**順序の破れは起きない。**

### 5-2. なぜ文字を canvas に描かないか

1. **ホバー説明（R-933）を1つの仕組みに統一できる。** ドックのバーにも盤面の区画名にも同じツールチップが要る。
   **canvas に描いた文字にはツールチップを付けられない。** 14 §9.1 も同じ結論
2. **読める・選べる。** 文字はブラウザに任せたほうがきれいで、拡大しても崩れない
3. **actors レイヤが軽くなる。** 名札を毎フレーム `measureText` して角丸を描くのが、いまの `dish.js:199-214`

**例外：木・岩・小屋のような固定の風景に添える文字は terrain に焼いてよい。** 動かないし、リサイズのときしか描かれない。

## 6. 座標系

### 6-1. 投影は 14 §2 に従う（この文書では決めない）

14 は極座標を採る。**円ではなく楕円**に伸ばす（`#stage` が 900×744 と横長なので、真円だと左右が余る）。

```js
project(r, th)   => { x: cx + r*Rx*cos(th), y: cy + r*Ry*sin(th) }   // r は 0..1.16
unproject(x, y)  => { r: hypot((x-cx)/Rx, (y-cy)/Ry), th: atan2(...) }
```

**この非等方（Rx ≠ Ry）は個体を歪めない。**
`project()` が返すのは**ピクセル座標**で、個体はそこにピクセル半径の真円として描かれる。
→ **`ctx` に非等方の `scale()` を掛けないこと。** 掛けると個体が楕円になり、線幅も方向で変わる。
**細胞は円でなければ数えられない。** ここは特に効く。

`view` として各レイヤに配る値：

```js
{ w, h, dpr,                 // 論理px と画素密度
  rect,                      // {x,y,w,h} 描画領域
  cx, cy, Rx, Ry, Rbar,      // 投影のパラメータ（14 §2.2）
  project(r, th), unproject(x, y) }
```

### 6-2. `rect` は窓のリサイズでしか変わらない（X-05 で変更）

**旧版 §4-2 は破棄した。** 旧版は個体パネルの開閉で `rect.x` をずらし、150ms 補間するあいだ
terrain を CSS の `transform` でずらす、という設計だった。

`REQUIREMENTS` X-05 の裁定：**個体パネルは盤面を覆わないだけでなく、縮めもしない**（ドックに重なる層に出す）。
理由の1つは描画班の警告そのもの——パネル開閉のたびに `rect` が変わると terrain の焼き直し（28ms）が走る。

→ **`dish.setRect()` は窓のリサイズだけで呼ぶ。** 150ms 補間も transform ずらしも要らなくなった。
　`_rectAnim()` は残すが、呼ばれるのはリサイズのデバウンス後だけになる。

### 6-3. devicePixelRatio

```js
dpr = Math.min(2, devicePixelRatio || 1);
canvas.width  = Math.round(論理幅 * dpr);
canvas.height = Math.round(論理高 * dpr);
canvas.style.width = 論理幅 + 'px';
ctx.setTransform(dpr, 0, 0, dpr, 0, 0);   // 以後は論理px で描ける
```

- **2 で頭打ちにする。** 3以上の画面で 3 を使うと面積が 2.25 倍になり、`clearRect` の固定費が増える
- **起動時に1回読んで終わりにしない。** ウィンドウを別のモニタへ動かすと変わる。リサイズのたびに読み直し、変わっていたら3枚とも作り直す
- **`setTransform` を毎回使う。** `scale()` を累積させない。`scale()` を2回呼んで4倍になる事故は必ず起きる
- **細胞の下限 `rc ≥ 1.10` は論理pxで持つ**（§2-2）。dpr 1 の画面では実画素 2.2px になる。
  **dpr が 1 のときは細胞の段を1段落とすこと**（`cellsThatFit()` の `RC_MIN` を 1.10 → 1.6 に切り替える）

### 6-4. terrain を焼き直す条件

14 §10.3 のキャッシュキーに `dpr` を足す（モニタ間の移動で変わる）。

```
`${rectW}x${rectH}|${dpr}|${囲いの辺数}|${Math.round(land*2)}|${村はずれが開いているか}|${各区画が0人か}|${collapsing}`
```

**民心と恨みは入れないこと。** field レイヤの担当（§4-2・§4-3）。terrain に入れると 28ms が世代ごとに走る。
`land` は1世代 0.3 しか動かないので、0.5 刻みに丸めれば焼き直しは数世代に1回。**28ms が数世代に1回なら見えない。**

## 7. 時計と dt

### 7-1. 時計を2本に分ける

`main.js:120-122` にこう書いてある：

> requestAnimationFrame ではなくタイマーで回す。rAF は裏タブで止まるので、タブを切り替えただけで世界の時計まで止まってしまう。

**この判断は正しい。世界の時計は `setInterval` のままにする。**
まちがっているのは、**同じループで絵も描いていること**。裏タブで絵を描く意味はないし、
`setInterval` は裏タブで1秒に1回まで絞られるので、そこから出てくる `dt` が巨大になる。−741045 事故の入口はここ。

| | 動かすもの | 裏タブで止まる？ | dt の出どころ |
|---|---|---|---|
| **世界の時計** | `setInterval(worldTick, 33)` | 止まらない（絞られるだけ） | `performance.now()` の差。上限は1世代ぶん |
| **絵の時計** | `requestAnimationFrame(frame)` | 止まってよい | rAF が渡す時刻の差。上限は 50ms |

**この2つの dt を混ぜない。** 世界の dt を絵に渡さない。絵の dt で世界を進めない。

（いまの `main.js:156` は `Math.min(0.1, (now - lastDraw)/1000)` で切っていて、意図も注釈も正しい。
　直すのは「切り方」ではなく「dt を式に入れる構造」のほう。§8-2）

### 7-2. タブから戻ってきたとき

```
on visibilitychange → visible:
    lastFrameMs = performance.now()      // ★ 先に時計を進めておく
    markDirty(TERRAIN | FIELD)           // ★ 中身が捨てられている可能性
    requestAnimationFrame(frame)
```

`lastFrameMs` を先に更新しないと、次の `frame()` が「寝ていた時間ぜんぶ」を dt として受け取る。
`markDirty` を立てるのは、メモリ逼迫時にブラウザが canvas の中身を捨てることがあるため。
**捨てられたことは JS から分からない。** 分からないなら、戻るたびに描き直せばよい。28ms は一度きりなら見えない。

### 7-3. 世界が追いついたぶん

裏タブで寝ていたぶん、世界は何世代も進む。`main.js` の追いつき
（`while (acc >= step && guard++ < TICKS_PER_GEN)`）はそのまま残す。

**追いついた結果、個体が大量に生まれ、大量に死んでいる。**
`sync()` がそれを見て新しい個体を「中心から」湧かせると、戻った瞬間に50人が中心から飛び散る。
→ **新しい個体は席の位置に直接置く**（§9-1）。

## 8. 個体の運動

### 8-1. なぜ −741045 が出たのか（数式で確定させた）

いまの式（`dish.js:123-126`）：

```js
s.vx += (tx - s.x) * 0.0026 * dt * 60;
s.vx *= 0.90;
s.x  += s.vx;
```

誤差 `e = x - 目標`、減衰 `d = 0.90`、実効ばね定数 `k = 0.0026 × dt × 60` と置くと：

```
e[n+1] = (1 - d·k)·e[n] + d·v[n]
v[n+1] =    (-d·k)·e[n] + d·v[n]
```

この行列は `det = d = 0.9`、`tr = 1 + d - d·k`。離散系の安定条件は `|det| < 1` かつ `|tr| < 1 + det`。よって：

```
0.9 · k < 3.8   →   k < 4.222   →   dt < 27.07 秒
```

**dt が 27.07 秒を超えた瞬間、数学的に発散する。** 収束するかしないかで、途中はない。

dt=120秒（P1 の1世代）のとき、1px のずれが座標いくつになるか：

```
1フレーム後       -16
2フレーム後       236
3フレーム後     -3,513
4フレーム後     52,306
5フレーム後   -778,707   ← 報告された -741045 と同じ桁・同じ符号
6フレーム後 11,593,043
```

**「-741045」は、dt に1世代ぶん（120秒）が入って5フレーム回った値そのもの。** 原因は確定した。

### 8-2. 直し方：上限を切るのではなく、固定ステップにする

いまのコードは `dish.js:98` と `main.js:156` の**2か所**で上限を切っている。コメントも丁寧に書いてある。
**だがそれでも事故は起きた。**「上限を切る」方式は、**切り忘れたら死ぬ**という性質が永久に残る。
呼び出し元が増えるたびに同じレビューをやり直すことになる。

**決定：ばねを固定ステップで積分する。**

```
STEP = 1 / 60                             // 積分の刻みは定数。dt から作らない
MAX_SUB = 3                               // 1フレームで進める最大ステップ数

frame(dt):
    acc += clamp(dt, 0, STEP * MAX_SUB)   // = 0.05秒。念のための2重の柵
    let n = 0
    while acc >= STEP and n < MAX_SUB:
        integrate(STEP)                   // ← k は常に 0.0026。dt が式に入らない
        acc -= STEP
        n++
    if acc > STEP * MAX_SUB: acc = 0      // 追いつけないぶんは捨てる（借金を溜めない）
```

これで **`k` は定数 0.0026 になり、`dt` が式から消える。発散は構造的に起こりえない。**

`node` で確かめた（400px ずれた個体を5秒ぶん。理想は 300 ステップ）：

| フレームレート | 5秒で進んだステップ数 | 5秒後の位置 |
|---:|---:|---:|
| 144fps | 299 | 0.02 |
| 60fps | **300** | 0.02 |
| 30fps | **300** | 0.02 |
| 20fps | **300** | 0.02 |
| 15fps | 225 | 0.29 |
| 10fps | 150 | 4.05 |

**20fps までは、フレームレートが変わっても動きが1ステップも変わらない。**

`MAX_SUB=3` の意味：1フレームで最大 50ms ぶんしか動かさない。15fps を割ると**わざと遅れる**。
追いつかせようとすると遅い環境でさらに重くなる（死のスパイラル）。**遅れて構わない。飛ぶよりよい。**

### 8-3. 最後の柵は残す

固定ステップにしても、目標に `NaN` が来たら（`slots.js` がバグったら）壊れる。
`dish.js:130-133` の「非有限・画面外なら目標位置へワープさせる」は**そのまま残す**。良いコードなので消さないこと。

```js
if (!Number.isFinite(s.x) || !Number.isFinite(s.y)
    || Math.abs(s.x - view.cx) > 4 * view.Rx
    || Math.abs(s.y - view.cy) > 4 * view.Ry) {
  s.x = tx; s.y = ty; s.vx = 0; s.vy = 0;
}
```

判定を画面幅ではなく `Rx`/`Ry` 基準にした。`rect` が変わっても意味が変わらないため。

### 8-4. ゆらぎ

`this.time` は**固定ステップの積算**にする（実時間ではなく `STEP` の累積）。
そうしないと、フレームレートによってゆらぎの速さが変わる。

**旧版は「ゆらぎの幅＝疲れ」に割り当てていた。捨てた**（A-5 で疲れは明度＋アイコン）。
ゆらぎは意味を持たない飾りなので、間引きの第2段で真っ先に止める（§10-3）。

**ゆらぎの幅は R の 6% を超えないこと。** 超えると細胞の粒が動いて見え、数えるのを邪魔する。

## 9. 入退場（生まれる・死ぬ）

いまの `sync()` は、新しい個体を**中心から 40〜70px の位置に湧かせ**（`dish.js:81-86`）、
死んだ個体を**その場で `pos.delete()`** している（`dish.js:89`）。どちらも変える。

### 9-1. 生まれる

**`slots.acquire(id)` が返した席に直接置く。** 14 §5.2 のゆらぎ（±0.22×pitch）ぶんだけばらける。
そこから 0.45秒で「ふくらむ」（半径 0 → 本来の半径）。

理由：裏タブから戻ったとき、追いついたぶんの新生児が全員中心から飛び散るのを防ぐため（§7-3）。
それに、子は集落（`home`）に置かれるので、中心から湧いて集落へ飛ぶ動きには意味がない。

**ふくらむあいだ、細胞は1個・年輪は0本のまま**（子どもはそもそもそうなる）。
半径だけが伸びるので、`cellsThatFit()` が途中で段を上げ下げして粒がちらつくことはない。

### 9-2. 死ぬ

**0.8秒かけて消す。** 半径を 0.8倍まで縮め、不透明度を 0 まで落とし、
同時に**彩度を 0.6秒で 0 へ**（§2-8）。そのあいだ位置は止める。

これは飾りではない。**03班の「戦死の94%が画面に出ない」への、描画側からの答え**。
`pos` から即 `delete` すると、人が消えたことが1フレームも画面に出ない。0.8秒残れば「減った」ことが目に入る。

**席は死んだ瞬間に返す**（`slots.release(id)`）。退場アニメ中の個体は席を占めない。

```
sync(world):
    frameNo++
    for p in world.people:
        if not pos.has(p.id): spawn(p)          // 席の位置に置く
        s = pos.get(p.id); s.seen = frameNo
        s.last = snapshot(world, p)             // ★ 消えた後で使う（下記）
    for [id, s] of pos:
        if s.seen != frameNo and s.fadeOut == null:
            s.fadeOut = 0; slots.release(id)    // 退場開始・席は即返す
        if s.fadeOut != null and s.fadeOut >= 0.8:
            pos.delete(id)                      // ここでだけ消す
```

**注意：`world.people` から消えた個体は、もう `p.genes` も `p.lineage` も `p.skills` も引けない。**
退場アニメに要る値は、消える前の最後のフレームで `s` にコピーしておくこと。

```js
// 毎フレーム入れ直す。150体で 0.05ms 未満（hsl 文字列150本が 0.014ms）
s.last = { fill, ink, R, cells: cellCount(p), rings: ringCount(p) };
```

**細胞と年輪も一緒に保存すること。** 旧版は色と半径しか保存していなかった（`s.lastColor` / `s.lastR`）。
新記号では細胞の数と年輪の本数がないと絵にならない。

## 10. フレーム予算と間引き

### 10-1. 予算は「総弧数」で持つ

1フレーム = 16.6ms（60fps）。全部を描画に使えるわけではない。

| 用途 | 予算 |
|---|---:|
| ブラウザの合成・スタイル計算・GC | 6.0 ms |
| DOM（ドックの再描画。250msに1回だが、来るときは来る） | 4.0 ms |
| **描画（actors レイヤ）** | **4.0 ms** |
| よゆう | 2.6 ms |

**旧版は「1体 10μs」という形で持っていた（4.0ms ÷ 400体）。捨てる。**
理由は2つある。

1. **400体は起きない。** R-103（村は10体で止まる）と R-301（P2 は100体で終わる）が実装されれば実用上の最大は150。
   実測でも40世代後の人口は 61〜173（中央値 102）。
   **400体を60fpsで美しく描くために設計を歪めないこと。** `MAX_POP = 400` は安全弁（`constants.js:19`）であって目標ではない
2. **「1体あたり」では検算できない。** 新記号は個体ごとに絵の重さが違う（弧2本〜12本）。
   平均で持つと、老人と熟練者が集まった村で静かに超過する

**→ 予算：1フレームの `arc()` の総数を 1,800本以内に収める。**

```
4.0 ms ÷ 2.2 μs/弧 = 1,818 本
```

- 実勢（§1-4）：人口150で **895本**（1.91ms）。**予算の 49%**
- 全員が最悪（年輪3＋細胞7＋膜＋黒円＝12本）：人口150で **1,800本**（3.2〜3.4ms）。**ぎりぎり収まる**
- 人口が 150 を超えたら 1,800 ÷ 人口 が1体あたりの上限。**そこから段を落とす**（§10-3）

**この予算は誰でも検算できる。** `dish.js` で `arcCount` を数えて `console` に出せば済む。
受け入れ条件 E-5 はこれを使う。

### 10-2. 超えたときの測り方

1フレームだけ見て判断しない。重い1フレーム（GC など）で品質を落とすと、次で戻して、また落として、とちらつく。

```
frameCost[] = 直近60フレームの actors 描画時間
median = frameCost の中央値          // 平均ではなく中央値。外れ値に引きずられない
if median > 5.0ms  かつ  30フレーム連続で超過:  品質を1段下げる
if median < 2.5ms  かつ 120フレーム連続で下回る: 品質を1段上げる
```

上げる条件を下げる条件より**厳しく**してある（120 vs 30フレーム）。行き来を防ぐため。

### 10-3. 落とす順番（A-4 で中身が変わった）

上から順に落とす。**いちばん下は絶対に落とさない。**

| 段 `lod` | 落とすもの | 減る弧数／効き |
|---|---|---|
| 0 | （落とさない）全部 | 平均 5.98本／体 |
| 1 | **年輪の段を1段粗くする**（最大3本 → 2本） | −0.5本／体 |
| 2 | **年輪をやめる。**膜と細胞だけ | −1.4本／体（**24%減**） |
| 3 | **ゆらぎを止める。**席に静止 | 計算が減り、絵が安定して**細胞が数えやすくもなる** |
| 4 | 資源の三角の粒数を 48 → 16 に減らす | 小 |
| 5 | actors レイヤを2フレームに1回だけ描く | 実効半分 |
| — | **細胞の数** | **絶対に落とさない。**A-4 の「数えられることが生命線」 |
| — | **色相・位置・大きさ**（＝血すじ・居場所・年齢） | **絶対に落とさない。これがこのゲームの中身** |
| — | **弱りの黒円** | **絶対に落とさない。**1本しかないうえ、A-5 が盤面に残した唯一の状態表示 |

**年輪を先に落とす理由**：年齢は**大きさでも読める**（§2-4）。年輪が消えても年齢が完全に消えるわけではない。
細胞の数には代わりのチャンネルが無い。だから最後まで残す。

**半径による自動の段落としは §2-5 の `cellsThatFit()` / `ringsThatFit()` がやる。**
`lod` とは別の仕組みで、こちらは「読めるかどうか」、`lod` は「間に合うかどうか」を見ている。混ぜないこと。

## 11. ヒットテスト

### 11-1. 個体

**線形走査でよい。** 実測 400体で 0.005ms。空間分割は要らない（§1-7）。

```
pick(mx, my):
    best = null; bestD = ∞
    for [id, s] of pos:
        if s.fadeOut != null: continue          // 消えかけは拾わない
        r = 描画半径(id)
        hit = max(r + 4, 14)                    // 最低でも半径14pxは押せる
        d = (s.x-mx)² + (s.y-my)²
        if d < hit² and d < bestD: bestD = d; best = id
    return best
```

**`max(r + 4, 14)` に統一する。** 旧版は `max(r+4, 11)`、13 は `max(r+4, 14)`、12 は `max(半径+6, 14)` と
3つの文書で3つの式になっていた（`99-抜けの指摘.md` の指摘）。
**下限は 14 に揃える**（12 と 13 の多数、かつ大きいほうが安全）。式は `r + 4` を採る。
**最終的な確定は UI班が盤面の寸法表に1か所書き、本書はそれを引用する形にする**（§15-3）。

いまの `dish.js:50` は `bd = 22*22` の固定値で、**描画半径を見ていない**。
`base` の下限を 10 に上げても（§2-6）、大人の R は 10〜13。22px の判定は**見た目の 1.7〜2.2倍**で、
円のない場所を押すと隣が選ばれる。**半径に連動させること。**

### 11-2. 区画

14 §9.1 のとおり `unproject()` → `(r, θ)` → 区画表の照合で済む。走査すら要らない。
**個体が取れなかったときだけ区画を見る**（個体が手前）。

### 11-3. ホバーは毎フレーム計算し直す

**いまの実装のバグ：`_mouse()` は `mousemove` のときにしか呼ばれない**（`dish.js:34`）。
個体は動いているので、**マウスを止めたまま、指している相手が入れ替わる**。名札は前の人のまま残る。

```
frame():
    if modalOpen(): hover = null; return
    if not pointer.inside: hover = null; return
    hover = pick(pointer.x, pointer.y) ?? wardAt(pointer.x, pointer.y)
```

コストは 0.005ms。毎フレームやって構わない。

### 11-4. 座標の取り方

```js
const r = stage.getBoundingClientRect();
mx = e.clientX - r.left;
my = e.clientY - r.top;
```

`canvas` ではなく **`#stage` の rect を使う**。canvas は3枚ある。

overlay の中の DOM（名札・区画ラベル）にも `pointer-events: none` を付ける。
**ただし §4-5 のツールチップを出す要素だけは `pointer-events: auto`** にする。

既知バグ（04班）：`.scrim{top:60px}` なので幕がトップバーを覆わず、決断待ちのモーダルの裏で時間を進められる。

## 12. 盤面が消えないための約束

既知バグ：起動直後、canvas が 2×2 ピクセルのまま真っ黒。25秒後も直らなかった回がある（02班）。
原因は `dish.js:42` の `Math.max(1, r.width)` — **rect が 0 のときに「1」を正解として焼き付けてしまう**こと。

### 約束1：サイズが 0 のときは、何も決めない

```js
measure() {
  const r = stage.getBoundingClientRect();
  if (r.width < 2 || r.height < 2) { this.layoutReady = false; return false; }
  this.layoutReady = true;
  ...
}
```

**`Math.max(1, ...)` を書かない。** 0 を 1 に化かすと「幅1px」が正しい値として保存され、
次のフレームで「変わっていない」と判定される。**これがバグの本体。**

### 約束2：`layoutReady` が false のあいだは描かない。ただしループは止めない

rAF は回し続け、毎フレーム `measure()` を試す。DOM が整った瞬間に自動で復帰する。
**「1回失敗したら諦める」経路を作らないこと。**

### 約束3：サイズが変わったら3枚とも作り直し、全部 dirty にする

`canvas.width` に代入すると**中身は消える**（同じ値を代入しても消える）。
`width`/`height` を触ったら、そのレイヤは必ず描き直す。

### 約束4：リサイズ中は焼き直さない（デバウンス）

terrain の焼き直しは 28ms。ウィンドウのドラッグ中に毎回やると固まる。

```
onResize:
```

## 13. オフスクリーンに焼く（キャッシュ）

### 13-0. これは「スプライト（画像素材）」ではない ★誤解を防ぐための明記

オーナーが禁じたのは **「スプライト（画像素材）は入れない」**（07 A-1）＝
**プロジェクトに画像ファイルを持ち込むこと**である。禁止の理由は
「絵を外注した見た目にしない／Canvas の手続き描画だけで解く」ことにある。

ここで言う「焼く」は、**その場のコードが `arc()` と `fill()` で描いた結果を、
見えないオフスクリーン canvas に一時的に置いて使い回す**というだけの最適化である。

| | 禁じられたスプライト | ここで言う「焼く」 |
|---|---|---|
| 絵の出どころ | `.png` などのファイル | **コードの `arc()` / `fill()`** |
| リポジトリに増えるもの | 画像ファイル | **何も増えない** |
| 色や形を変えるには | 画像を描き直す | **コードの数字を変える** |
| 消しても絵は出るか | 出ない | **出る**（直接パスに戻るだけ） |

**この最適化を「スプライト」と呼ばないこと。** 文書でもコードでも `bake` / `焼く` と書く。
呼び名が混ざると、禁止された話とレビューで混同される。

### 13-1. 盤面では焼かない（§1-5 の実測による）

再掲：直接パス 20.0μs/体 に対して、焼いて `drawImage` は 27.9〜61.0μs/体でぶれた。
さらに小数座標での再標本化でにじむ。**盤面（actors レイヤ）は直接パスで描く。**

### 13-2. 肖像は焼く（ここが本番）

DOM のパネルに並ぶ肖像（`color.js:165 portrait()`）は、いま**呼ぶたびに canvas を作っている**。
1体 78μs、150個で **11.71ms**。`main.js:161` はドックを 250ms ごとに描き直すので、
肖像が載るパネルが開いていれば1秒あたり 11ms を作り直しに払う。

```js
// ============================================================ src/ui/portrait-cache.js
const CACHE = new Map();       // id -> { canvas, sig }
const MAX = 400;               // 上限。超えたら古い順に捨てる（Map は挿入順を保つ）

/** 見た目が変わる値だけを並べる。frailty は入れない（下記） */
function signature(world, ind, size) {
  return [
    size,
    Math.round(hueOf(world, ind.lineage) * 2),   // 0.5°刻み。血すじ
    wedgeSig(ind.lineage),                       // 楔を採るなら混合比の署名（X-03 待ち）
    ringCount(ind),                              // 0..4
    cellCount(ind),                              // 1..7
    ind.alive === false ? 1 : 0,                 // 死は彩度が変わる
  ].join('|');
}

export function portrait(world, ind, size = 26) {
  const sig = signature(world, ind, size);
  const hit = CACHE.get(ind.id);
  if (hit && hit.sig === sig) { CACHE.delete(ind.id); CACHE.set(ind.id, hit); return hit.canvas; }

  const c = document.createElement('canvas');
  const dpr = Math.min(2, devicePixelRatio || 1);
  c.width = size * dpr; c.height = size * dpr;
  c.style.width = c.style.height = size + 'px';
  const g = c.getContext('2d');
  g.setTransform(dpr, 0, 0, dpr, 0, 0);
  drawActor(g, size / 2, size / 2, size * 0.40, stateOf(world, ind, { frailty: 0 }));  // ★ frailty は 0 で焼く

  CACHE.set(ind.id, { canvas: c, sig });
  while (CACHE.size > MAX) CACHE.delete(CACHE.keys().next().value);
  return c;
}

export function dropPortraits() { CACHE.clear(); }   // リサイズのデバウンス後・dpr 変更時に呼ぶ
```

#### 焼き直す条件（＝キャッシュキーに入れる値）

| 値 | 入れる？ | どれくらい変わるか |
|---|:--:|---|
| 表示サイズ | ○ | パネルごとに固定 |
| 血すじ（色相・混合比） | ○ | **一生変わらない**（`lineage` は誕生時に決まる） |
| 年輪の本数 0..4 | ○ | **一生に最大4回** |
| 細胞の数 1..7 | ○ | **一生に最大6回** |
| 生死 | ○ | 一生に1回 |
| **弱り `frailty`** | **✕** | **tick ごとに動く。**入れるとキャッシュが毎 tick 壊れる |

**弱りだけは焼かない。** 焼いた絵を貼ったあと、その上に黒円を重ねる（§2-7 と同じ手）。
`frailty` をキーに入れると、疲れが 0.01 動くたびに 78μs の焼き直しが走る。**これがいちばん大事な設計判断。**

#### 上限と失効

- 上限 **400枚**。1枚 26×26×dpr2 = 52×52×4byte = **10.8KB**。400枚で **4.3MB**。許容
- 超えたら**挿入順の古いほうから捨てる**（`Map` の反復順は挿入順なので、上のコードで LRU になる）
- **`dpr` が変わったら全部捨てる**（`dropPortraits()`）。モニタ間の移動で起きる
- **死んだ個体のぶんは残してよい。**年代記や検索で後から出る。上限に任せる

#### 効果の見積り

150個の肖像を出すパネルで、初回 11.71ms。2回目以降は署名が一致するので **0ms**。
250ms ごとのドック再描画（26個）は初回 2.72ms → 以降 0ms。

### 13-3. 盤面用の非常口（条件つき。既定では作らない）

キャラ班（13）が個体の絵をもっと濃くして、§10-1 の **総弧数 1,800本を恒常的に超える**ようになったら、
そのときだけ盤面の焼きを検討する。**そのときも、まずベンチに足して測ること。**
測らずに入れると、§1-5 のとおり遅くなる可能性のほうが高い。

盤面で焼く場合のキーは肖像と同じ（サイズは R の段に置き換える）。
**個体は毎フレーム動くので、貼る位置は `Math.round()` しないこと**（動きがカクつく）。
にじみを受け入れるか、動きのなめらかさを取るかの二択になる。**この二択が発生する時点で、直接パスのほうがよい。**

```js
    this.actors  = addCanvas(stage, 'layer-actors',  3);
    this.overlay = addDiv   (stage, 'layer-overlay', 4);

    this.pos   = new Map();      // id -> {x,y,vx,vy,ph,fadeIn,fadeOut,last,seen}
    this.slots = new RegionSlots();
    this.view  = { w:0, h:0, dpr:0, rect:{x:0,y:8,w:0,h:0} };
    this.dirty = DIRTY.TERRAIN | DIRTY.FIELD;
    this.layoutReady = false;
    this.bakeKey = '';
    this.acc = 0; this.animTime = 0; this.frameNo = 0;
    this.lod = 0; this.cost = new Ring(60); this.arcs = 0;
    this.shown = { morale: 0.6, grudge: 0 };     // §4-2・§4-3 の追従値
    this.hover = null; this.selected = null;
    this.pointer = { x: 0, y: 0, inside: false };

    this.actors.el.addEventListener('mousemove',  e => this._pointer(e));
    this.actors.el.addEventListener('mouseleave', () => this.pointer.inside = false);
    this.actors.el.addEventListener('click', () => { if (this.hover != null) this.onPick(this.hover); });

    new ResizeObserver(() => this._onResize()).observe(stage);            // 約束7
    document.addEventListener('visibilitychange', () => {
      if (!document.hidden) { this.lastFrame = performance.now();         // 約束5
                             this.dirty |= DIRTY.TERRAIN | DIRTY.FIELD; }
    });
  }

  // ---------------------------------------------------------- 計測
  _measure() {
    const r = this.stage.getBoundingClientRect();
    if (r.width < 2 || r.height < 2) { this.layoutReady = false; return false; }  // 約束1
    const dpr = Math.min(2, devicePixelRatio || 1);
    const changed = r.width !== this.view.w || r.height !== this.view.h || dpr !== this.view.dpr;

    this.view.w = r.width; this.view.h = r.height; this.view.dpr = dpr;
    regions.layout(this.view);                     // rect / cx / cy / Rx / Ry / Rbar（14 §2.2）

    if (changed) {                                                        // 約束3
      for (const L of [this.terrain, this.field, this.actors]) resize(L, r.width, r.height, dpr);
      this.dirty |= DIRTY.TERRAIN | DIRTY.FIELD;
      dropPortraits();                                                    // 約束4（§13-2）
    }
    this.layoutReady = true;
    return true;
  }

  _onResize() {
    this._measure();
    clearTimeout(this._bakeT);                                            // 約束4
    this._bakeT = setTimeout(() => { this.dirty |= DIRTY.TERRAIN; }, 120);
  }

  setRect(part) { this._rectTarget = { ...this.view.rect, ...part }; }    // 窓のリサイズだけ（X-05）

  // ---------------------------------------------------------- 名簿の同期
  sync(world) {
    this.frameNo++;
    const base = regions.dotBase(world, this.view);        // 14 §5.3（下限 10.0 / 段でしか動かない）
    for (const p of world.people.values()) {
      let s = this.pos.get(p.id);
      if (!s) {
        const t = this._target(p, world);                  // §9-1 席の位置に置く
        s = { x: t.x, y: t.y, vx: 0, vy: 0, fadeIn: 0, fadeOut: null, ph: hash01(p.id, 0x51ed) * 100 };
        this.pos.set(p.id, s);
      }
      s.seen = this.frameNo;
      // ★ 消えた後で使う。細胞と年輪も保存すること（§9-2）
      s.last = { fill: bodyColor(world, p), ink: bodyInk(world, p), R: radiusOf(p, base),
                 cells: cellCount(p), rings: ringCount(p), frailty: frailty(p) };
    }
    for (const [id, s] of this.pos) {
      if (s.seen !== this.frameNo && s.fadeOut == null) {
        s.fadeOut = 0; this.slots.release(id);             // 退場開始・席は即返す
      }
      if (s.fadeOut != null && s.fadeOut >= 0.8) this.pos.delete(id);
    }
  }

  // ---------------------------------------------------------- 運動（固定ステップ）
  update(world, dtSec) {
    this.acc += clamp(dtSec, 0, STEP * MAX_SUB);                          // 2重の柵（=0.05秒）
    let n = 0;
    while (this.acc >= STEP && n < MAX_SUB) { this._integrate(world, STEP); this.acc -= STEP; n++; }
    if (this.acc > STEP * MAX_SUB) this.acc = 0;                          // 借金を溜めない
  }

  _integrate(world, h) {
    this.animTime += h;
    flow.step(h, world, this.view);
    // 民心・恨みの追従（§4-2）。時定数 0.2 秒。h から作るので fps に依存しない
    const a = 1 - Math.exp(-h / 0.2);
    const before = this.shown.morale + this.shown.grudge;
    this.shown.morale += ((world.morale ?? 0.6)      - this.shown.morale) * a;
    this.shown.grudge += ((world.regimeGrudge ?? 0)  - this.shown.grudge) * a;
    if (Math.abs(this.shown.morale + this.shown.grudge - before) > 1e-4) this.dirty |= DIRTY.FIELD;

    const K = 0.0026, D = 0.90;              // ★ h も dt も掛けない。定数
    for (const p of world.people.values()) {
      const s = this.pos.get(p.id); if (!s) continue;
      const t = this._target(p, world);
      s.vx += (t.x - s.x) * K; s.vy += (t.y - s.y) * K;
      s.vx *= D; s.vy *= D;
      s.x += s.vx; s.y += s.vy;

      const v = this.view;                                                // §8-3 最後の柵
      if (!Number.isFinite(s.x) || !Number.isFinite(s.y)
          || Math.abs(s.x - v.cx) > 4 * v.Rx || Math.abs(s.y - v.cy) > 4 * v.Ry) {
        s.x = t.x; s.y = t.y; s.vx = 0; s.vy = 0;
      }
      if (s.fadeIn  <  1)    s.fadeIn  = Math.min(1, s.fadeIn + h / 0.45);
      if (s.fadeOut != null) s.fadeOut += h;
    }
  }

  _target(p, world) {
    const key  = regions.wardKey(p.role, p.district);
    const slot = this.slots.acquire(key, p.id);
    const dest = regions.slotToPolar(key, slot, this.slots.count(key), this.view);
    const road = this.slots.transitRoad(p.id, key);        // 区画が変わった直後だけ非null
    const pol  = road ?? dest;
    return this.view.project(pol.r, pol.th);
  }

  // ---------------------------------------------------------- 描画
  draw(world) {
    if (!this.layoutReady) return;                                        // 約束2

    // --- terrain：キャッシュキーが変わったときだけ（§6-4）
    const key = terrain.cacheKey(world, this.view);
    if ((this.dirty & DIRTY.TERRAIN) || key !== this.bakeKey) {
      const g = begin(this.terrain, this.view);
      g.clearRect(0, 0, this.view.w, this.view.h);
      terrain.paint(g, this.view, world);
      this.bakeKey = key; this.dirty &= ~DIRTY.TERRAIN;
      this._syncWardLabels(world);
    }

    // --- field：tick ごと ＋ 補間中は毎フレーム
    if ((this.dirty & DIRTY.FIELD) || terrain.interpolating()) {
      const g = begin(this.field, this.view);
      g.clearRect(0, 0, this.view.w, this.view.h);
      terrain.paintGranary(g, this.view, world);                          // 蔵ゲージ
      terrain.paintWardMood(g, this.view, world);                         // 区画の点灯／沈み
      terrain.paintFenceMorale(g, this.view, world, this.shown.morale);   // §4-2 ほどけ
      terrain.paintCracks(g, this.view, world, this.shown.grudge);        // §4-3 ひび
      this.dirty &= ~DIRTY.FIELD;
    }

    // --- actors：毎フレーム
    const t0 = performance.now();
    const g = begin(this.actors, this.view);
    g.clearRect(0, 0, this.view.w, this.view.h);
    this.arcs = 0;

    flow.draw(g, this.view);
    for (const id of this._drawOrder(world)) {                            // 村はずれ→まんなか、選択は最後
      const s = this.pos.get(id), L = s.last;
      const R = L.R * (0.3 + 0.7 * s.fadeIn)
                    * (s.fadeOut == null ? 1 : 1 - 0.2 * (s.fadeOut / 0.8));
      g.globalAlpha = s.fadeOut == null ? 1 : Math.max(0, 1 - s.fadeOut / 0.8);
      const st = { cells: L.cells, rings: L.rings, frailty: L.frailty,
                   fill: s.fadeOut == null ? L.fill : desaturate(L.fill, s.fadeOut / 0.6),  // §2-8
                   ink: L.ink, hover: this.hover === id, selected: this.selected === id,
                   fadeIn: s.fadeIn, fadeOut: s.fadeOut, lod: this.lod };
      drawActor(g, s.x, s.y, R, st);
      this.arcs += 1 + (this.lod < 2 ? st.rings : 0) + st.cells + (st.frailty > 0 ? 1 : 0);
    }
    g.globalAlpha = 1;
    terrain.paintSelectionAndGate(g, this.view, world, this.selected);    // 個体より上
    this.cost.push(performance.now() - t0);
    this._autoLod();                                                      // §10-2

    this._syncNameplate(world);                                           // overlay の DOM
  }

  // ---------------------------------------------------------- 入力
  _pointer(e) {
    const r = this.stage.getBoundingClientRect();                         // §11-4
    this.pointer.x = e.clientX - r.left;
    this.pointer.y = e.clientY - r.top;
    this.pointer.inside = true;
  }

  pickTick(world) {                                                       // §11-3 毎フレーム
    if (modalOpen() || !this.pointer.inside) { this.hover = null; this.hoverWard = null; return; }
    let best = null, bd = Infinity;
    for (const [id, s] of this.pos) {
      if (s.fadeOut != null) continue;
      const hit = Math.max(s.last.R + 4, 14);                             // §11-1
      const d = (s.x - this.pointer.x) ** 2 + (s.y - this.pointer.y) ** 2;
      if (d < hit * hit && d < bd) { bd = d; best = id; }
    }
    this.hover = best;
    this.hoverWard = best ? null : regions.wardAt(this.pointer.x, this.pointer.y, this.view);
    this.actors.el.style.cursor = (best || this.hoverWard) ? 'pointer' : 'default';
  }

  // ---------------------------------------------------------- 品質の自動調整
  _autoLod() {
    const m = this.cost.median();
    if (m > 5.0) { if (++this._over  >=  30) { this.lod = Math.min(5, this.lod + 1); this._over  = 0; } }
    else this._over = 0;
    if (m < 2.5) { if (++this._under >= 120) { this.lod = Math.max(0, this.lod - 1); this._under = 0; } }
    else this._under = 0;
    flow.setBudget(this.lod >= 4 ? 16 : 48);                              // §10-3 第4段
  }
}

function begin(layer, view) {
  const g = layer.ctx;
  g.setTransform(view.dpr, 0, 0, view.dpr, 0, 0);   // ★ scale() を累積させない（§6-3）
  return g;                                        // ★ 非等方 scale は掛けない（§6-1）
}

// ============================================================ main.js（新）
// 時計は2本（§7-1）。混ぜない。

setInterval(() => {                       // 世界の時計：裏タブでも止まらない
  const now = performance.now();
  const dt = Math.min(genMs(world), now - lastWorld); lastWorld = now;
  advanceWorld(dt);                       // ← ここは今のコードのまま
}, 33);

function frame(nowMs) {                   // 絵の時計：裏タブで止まってよい
  requestAnimationFrame(frame);
  const w = state.world; if (!w) { lastFrame = nowMs; return; }
  const dtSec = (nowMs - lastFrame) / 1000; lastFrame = nowMs;

  dish.sync(w);
  dish.update(w, dtSec);     // ← 中で固定ステップに切り分ける。dtSec が式に入ることはない
  dish.pickTick(w);
  dish.selected = state.selected;
  dish.draw(w);
}
requestAnimationFrame(frame);
```

### 18-2. 残る未決（オーナーまたは他班の裁定が要る）

1. **混血を「中間色」で描くか「楔（扇形）」で描くか**（X-03 / オーナー確認 Q-3）。
   本書の幾何（§2-2）は**どちらでも成立する**ように作ってある——楔は「塗り」の分割であって、
   核（細胞）にも帯（年輪）にも触れない。**楔になった場合、細胞と年輪は楔の境目をまたいで描く**こと
   （楔ごとに切ると、色の境目が細胞の輪郭に見えて数え間違いが起きる）。
2. **`base` の下限を 10.0 に上げてよいか**（§2-6 → 14）。
   面積は余ることを確認済みだが、区画ごとの席の詰まり具合は 14 が持っている。
   **上げられない場合、細胞は最大2個・年輪は最大2本になり、A-4 の「数えられる」が成立しない。**
   そのときは盤面をズームするか、区画の面積配分を変えるかの選択になる。**描画班からは 10.0 を強く推す**。
3. **アイコン15個の絵柄そのもの**（§3-1 で一覧は確定、§3-3 で作法も確定）。
   実際の `d` を書くのはキャラ班（13）。**一覧に無いものを足さないこと**が条件。
4. **`w.fear`（粛清の抑圧・`world.js:929`）を画面のどこかに出すか。**
   本書では盤面に出さないと決めた（§4-3 末尾）。個体詳細・報告に数字＋説明で出すかは UI班と用語班の判断。
5. **盤面の確定寸法表**（§15-3）。当たり判定の下限が3文書で3つある。UI班が1か所に書くまで、本書は `max(r+4, 14)` を使う。
