# 地図の配置要件（UI班 → キャラビジュアル班）

対象：`game2/src/ui/map.js` の `#map` 層（Canvas2D・地形／エリア／家の箱）。
**描き方は決めません。**「何が読めなければならないか」と「何を人に隠されると困るか」だけを書きます。

前提：個体は WebGL（`#actors`）で `#map` の上に**不透明に**乗る。名札は `#labels`（個体より上）。

## 0. 先に、前提の訂正を1つ

**旧 `docs/v3/14-設計-村マップ.md` の「半径＝中心か辺境か」は、もう使えません。**

旧設計は「同じ村の中で、中心に住む者と辺境に住む者が分かれる」前提でした。
いまの実装は違います。**中央／辺境は村ごとの属性です**（`villages.where`。`village.js:65`）。
村がまるごと中央か、まるごと辺境かのどちらかで、村の中に境目はありません。

だから：

- **村の中の半径は空いています。**仕事の配置に自由に使えます
- **中央と辺境の対比は、村と村の対比として、街のズームで出ます**
- いまの `AREA_FRONTIER` を「外周の帯」として描いているのは、**村の中の辺境ではなく、村のはずれ**の意味なら正しいです。A-21 の「辺境で育つと体と胆が伸びる」はこの帯ではなく `village.where` のほうです。**名前が同じで別物なので、名札の文言は私が引き取ります**

## 1. 読めなければならないもの（これが要件の全部）

A-19 が要件として書いているのは1行だけです。

> **誰がどこで何の仕事をしているかが、見て分かること**

そこに、崩壊条件（産出が消費を下回る）と村の上限（30軒）から3つ足します。

| # | 読めること | いまの状態 |
|---|---|---|
| **1** | **誰がどこで何の仕事をしているか** | ○ 済んでいる（エリア＋人数の名札） |
| **2** | **家が何軒埋まっているか。** 30軒で村が止まり、溢れが分村の引き金になる（A-19b） | ○ 30枠が最初から見えている形。**空き枠が見えるのが正しい**（埋まっていく先が分かる） |
| **3** | **畑と森が混んでいるか。** 産出が消費を下回るのが唯一の崩壊条件（柱6） | △ 人は立っているが、**混みすぎているのかどうかは読めない** |
| **4** | **蔵が満ちているか／減っているか** | **× 盤面に無い。**上帯の数字だけ |

**4が A-10 の穴です。**

> 守られた導入のあいだ**常に動いているものを3つ**。
> **細胞が増える**（練度）／**蔵が満ちる**（食料）／**季節が変わる**（10分＝10ヶ月なので冬が1回）

細胞は戻りました（`f1f7635`）。冬は畑が言っています。**蔵だけが盤面にありません。**
導入の8〜10分に「常に動いているもの」が2つしかない状態です。

**お願い：蔵を盤面に置いてください。** 置き場所は任せます。要件は3つだけ。

- **人が立たない場所に置く**（隠れると「動いているもの」の役をしない）
- **満ち／減りが、数字ではなく形で読めること**（A-1「まず絵で分かる。数字は裏づけ」）
- **1世代ぶんの線を引くこと。**「線より下は次の世代までもたない」（`world.eaten × 12` あたり。数は私が出します）

## 2. 人に隠れてよいもの／いけないもの

聞かれた件です。**判定はこれ1本で足ります。**

> **「動くもの（人）が上に乗る面には、動かないと読めないものを置かない。」**

| | 隠れてよい | 理由 |
|---|---|---|
| 地形の塗り、畝の線、木・杭・小屋の飾り | ○ | 量を意味しない固定の風景。一部が隠れても意味が変わらない |
| 家の箱の輪郭、エリアの境 | ○ | 形が大きいので、人が上に乗っても輪郭が追える |
| エリアの塗りの明暗（冬など） | ○ | 面全体の話なので、一部が隠れても読める |

| | 隠れてはいけない | どこへ回すか |
|---|---|---|
| **エリア名 ＋ 人数** | × | `#labels`（済んでいる） |
| **家の軒数・家ごとの人数** | × | `#labels`、または**人が立たない帯**（いまの `yardRect()` の対処で正しい） |
| **蔵の量と1世代線** | × | 人が立たない場所に置く（§1-4） |
| **冬の印** | × | 面の明暗で言うなら隠れてよい。文字で言うなら `#labels` |
| **数えるもの全部**（軒数・人数・蔵） | × | 数えられなくなった時点で嘘になる |

**`yardRect()` で人を家の前の庭に立たせて箱の数字と重ならないようにした判断は、この規則そのものです。**そのまま続けてください。

## 3. 面積が量を意味してはいけない

旧 `14 §0-3` の規則で、これは生きています。

- **エリアの広さを人数に比例させない。**人数は名札が言う
- 例外にしてよいのは畑だけです（旧設計は `world.land` に比例させ、「働き手が土地を超えると取り分が減る」を混み具合の絵として出していた）
- **ただし、いまの `village.js` に `land` がありません。**畑の広さは固定のままにしてください。
  可変にするのは、耕地が世界側に入ってからです。**私から設計班へ聞いておきます**

§1-3（混んでいるか読めない）は、`land` が無い以上、いまは**人の詰まり具合**でしか出せません。
`workers / 30` あたりで格子の間隔を詰める、程度で十分です。**急ぎません。**

## 4. ズームの段（いま作らなくていい。壊さないでほしいことだけ）

A-19 の最大の効能が、ここに乗っています。

> 村1つのときは家が見えて、誰がどこで何をしているか分かる。
> 街になると村が箱になり、**個人が見えなくなる**。国になると街が箱になる。
> フェーズ＝オーナーと国民の距離。**転換は解禁ではなく喪失**

**要件は2つだけです。**

1. **段が変わるのは、同じ画面の中であること。**別画面にしないでください。
   「画面から人が消えていく」が体感になるのが、この設計の値打ちなので
2. **村1つを描く関数が、村の座標と大きさを引数で受けられること。**
   街の段で同じ関数を30分の1の大きさで何十回も呼ぶことになります。
   `villageOrigin(k, n)` が既にその形なので、**そのまま続けてください**

`MAX_FOLK = 3000` を超えたら箱だけになる、という線が `run.js` に既にあります。
段の切り替えをそこに結びつけるかは、そちらの判断で構いません。
