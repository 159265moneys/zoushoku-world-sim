# game2 の骨組み

`確定事項.md` から、**ステの中身に依存しない部分だけ**を先に決めたもの。
実装に入る前の設計図。ステ定義v2 が上がったら、これに沿って書き始める。

---

## 1. 置き場所

- **`game2/` を `game/` の隣に作る。** `game/` は見本として残す
- `genetics.js` など移植するものは、**書き写すのではなく読んで移す**（劣化を避ける）
- Pages の公開は `game/` のまま。`game2/` が動くようになってから切り替える

---

## 2. データの持ち方（ここが旧版といちばん違う）

**列ごとの型付き配列（SoA）。オブジェクトの配列にしない。**

実測：10万人で 型付き配列 86MB／8.1ms、辞書＋オブジェクト 526MB／18.2ms。**6倍の差。**

```
people/
  gene[stat][i]     Float32Array   才能（生まれつき・不変）
  ev[stat][i]       Float32Array   努力値
  age[i]            Uint16Array    月齢
  sex[i]            Uint8Array
  house[i]          Uint32Array    どの家に属するか
  village[i]        Uint16Array    どの村か
  rank[i]           Uint8Array     身分
  post[i]           Uint8Array     ポジション
  state[i]          Uint32Array    状態異常のビット
  wealth[i]         Float32Array
  alive[i]          Uint8Array
```

**しがらみは別の配列（辺のリスト）**

```
ties/
  from[e]   Int32Array
  to[e]     Int32Array
  type[e]   Uint8Array    伴侶／恋人／親／子／恨み／借り…
  strength[e] Int16Array
  since[e]  Uint16Array   いつから（月）
```

実測：10万人×20本＝200万本で 1ヶ月8.1ms、40MB。**予算の0.03%。**

**1人あたりの線は150本を上限にする**（ダンバー数）。上限が無いと無限に増える。

## 3. 時間

```
tick = 1日
1ヶ月 = 30日  /  1年 = 12ヶ月 = 360日

1倍     … 1日 = 1分
本番上限 … 60倍（1ヶ月30秒・1年6分）
デバッグ … 500倍（開発用UIに隔離。本番に出さない）
```

- **Date.now() に依存した挙動を書かない。** 時間は tick で進める
- **月単位で計算するもの**：状態異常、産出、消費、成長
- **日単位で見せるもの**：季節、出来事の起きた日
- **戦闘だけ別の速さ**（ラウンド単位）
- **requestAnimationFrame を世界の時計に使わない。**
  旧版は戦闘だけ rAF のままで、タブが裏だと戦闘が進まなかった

## 4. 空間の階層

```
家（1家族）→ 村（30世帯・約100人）→ 街（村を並べる）→ 国（街を並べる）
```

- 村には**エリア**がある：家々／畑／森（狩猟）／訓練場／その他の仕事場
- **誰がどこで何をしているかが見て分かること**が要件。絵は線画と塗り分けで足りる
- **座標は UI 側だけが持つ。** sim は座標を知らない（旧版の規則を継承）
- ただし**「どの村か」「どの家か」は sim が持つ**（結婚の範囲・生産の計算に要る）

### フェーズ＝ズームの段

| ズーム | 見えるもの | 役職 | オーナーからの段数 |
|---|---|---|---|
| 家 | 個人 | 家長 | — |
| 村 | 家 | 村長 | 1段 |
| 街 | 村が箱になる | 街長 | 2段 |
| 国 | 街が箱になる | 9局長 | 3段 |

**ズームアウトすると個人が見えなくなり、同時に命令が通る段数が増えて歪みが重なる。**
これが「神から管理者へ落ちていく」の実装。

## 5. モジュールの分け方

```
game2/
  src/
    core/          共有契約。上位を知らない
      rng.js         決定性の乱数（game/ から移植）
      arrays.js      型付き配列の確保と拡張
      calendar.js    tick ↔ 日月年、季節

    world/         シミュレーション。DOM も window も知らない
      genes.js       ステの定義（ステ定義v2.csv から生成）
      genetics.js    遺伝の計算（game/ から移植。書き直さない）
      people.js      個体の配列と、生き死に
      ties.js        しがらみの辺
      house.js       家と家族
      village.js     村・エリア・生産
      marry.js       結婚と出産
      grow.js        加齢・努力値・デバフ
      war.js         戦争

    flow/          進行の順番を1か所に閉じ込める（旧版 flow/ の発想を継承）
      run.js         1日／1ヶ月／1年を進める
      stage.js       いま何ができるか
      notice.js      節目（初めて起きたこと）

    ui/            画面
      map/           地図の階層とズーム
      panel/         個体・家・村
      glossary.js    用語辞書（game/ から移植）

  test/
    check.js       継ぎ目の検査（旧版 flow.js の方法論を継承）
    converge.js    収束計（4つ）
```

### 守る規則（旧版から継承）

- **依存の向きは ui → flow → world → core の一方向**
- **UI は world を直接呼ばない。flow を通す**（旧版で G-18 として検査していた）
- **Math.random() を書かない。** 乱数は core/rng.js のみ
- 素のESモジュール。バンドラもフレームワークも使わない

## 6. 最初に作るもの（P1の村）

**順番。前のものが動くまで次へ行かない。**

1. **calendar.js と rng.js** … 時間が進むこと。同じ種から同じ歴史が出ること
2. **arrays.js と people.js** … 十匹が存在すること。歳を取ること
3. **house.js と village.js** … 家が30軒、エリアがあること。誰がどこにいるか
4. **grow.js** … 努力値が積まれること。年齢で減衰すること
5. **marry.js** … つがいができること。妊娠10ヶ月で生まれること
6. **地図の描画** … 家とエリアが見えること。誰がどこで何をしているか
7. **収束計** … 測れること

**1〜7が動いたら、それが「P1の始まりの村」。**

---

## 7. 先に作る検査（旧版の教訓）

> **sim単体とUI単体をいくら検証しても、繋いだ状態は検証されない。**
> 13項目が緑のままゲームが起動していなかった実例がある。

**検査台を最初に作る。** 中身は旧版の23項目を捨てて、新しく起こす。

最低限これだけは常に見張る：

- 同じ種から同じ歴史が出るか（決定性）
- 人口が爆発も絶滅もしないか
- NaN が出ないか
- 村が30軒で止まるか
- 妊娠が10ヶ月で終わるか
- **収束計4つ**（ステの分散／全ステ最強への接近／血統の生き残り／勝ち筋の一本化）

## 8. まだ決まっていないこと（実装前に要る）

- **1つの村に家は30軒で確定だが、溢れたときの分村の条件**（何軒目で開拓、何軒目で移住か）
- **エリアの広さは固定か可変か**（可変なら動詞「敷く」の使いどころ）
- **セーブの形**（IndexedDB を提案中。10万人＝40MB で localStorage は使えない）
- **信仰と評判の置き場所**（一任されている。地図と合わせて設計する）
- **出生率と死亡率の最終値**（1度測っただけ）
